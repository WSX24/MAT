# 课堂状态机规范（速查）

> **适用范围**：`TeachingFlow/classroom/` 的状态机实现（`state.py` 的 `Phase`、`machine.py` 的转移）。
> **这是 [`课堂交互设计.md`](课堂交互设计.md) 第 3 章的可实现精简版**，用于编码时的对照速查。

## 1. 状态枚举

```python
class Phase(str, Enum):
    LECTURING     = "LECTURING"      # 讲课,播讲解单元        [播放语音][可被打断]
    PAUSING       = "PAUSING"        # 探针等待,学生思考中     [可播话术][可被打断]
    ACKNOWLEDGING = "ACKNOWLEDGING"  # 已收到提问,播回执       [播短话术][不可打断]
    YIELDING      = "YIELDING"       # 讲完单元,播过渡,准备让位 [播短话术][不可打断]
    REDIRECTING   = "REDIRECTING"    # 回顾型:切页/定位后作答   [可视情况]
    ANSWERING     = "ANSWERING"      # 正在回答               [播放语音][只入队]
    RESUMING      = "RESUMING"       # 三步重入,回到被打断处    [含生成话术]
```

**状态唯一**：同一时刻只有一个 `phase`。个人自学场景不需要并行状态；唯一状态保证"老师现在在干什么"永远可答。

## 2. 转移表

| # | 当前 | 触发 | 下一个 | 动作 |
|---|---|---|---|---|
| 1 | — | 课堂开始 | `LECTURING` | 载入目标与第 1 页；播首个单元 |
| 2 | `LECTURING` | 单元播完，非页尾，队列空 | `LECTURING` | 播下一单元 |
| 3 | `LECTURING` | 单元播完，`is_page_end=True` | `PAUSING` | 播探针话术，开等待窗口 |
| 4 | `LECTURING` | **收到学生输入** | `LECTURING` | ①立即回执 ②入队 `pending_questions` ③**继续播完当前单元** |
| 4b | `LECTURING` | **收到翻页指令** | `LECTURING` | 立即执行；记 `user_advanced`；未确认项转 `deferred` |
| 5 | `LECTURING` | 单元播完，队列非空 | `YIELDING` | 播过渡话术 |
| 6 | `PAUSING` | 窗口内收到输入 | `YIELDING` | 关窗，播过渡话术 |
| 7 | `PAUSING` | 窗口超时无输入 | `LECTURING` | 记 `vague`；推进（保留事后回退入口） |
| 8 | `YIELDING` | 过渡话术播完 | `REDIRECTING` / `ANSWERING` | 按 `kind` 分流 |
| 9 | `REDIRECTING` | 切页/定位完成 | `ANSWERING` | 开始作答 |
| 10 | `ANSWERING` | 答案播完，队列空，学生无追问 | `RESUMING` | 三步重入 |
| 11 | `ANSWERING` | 学生说"没听懂" | `ANSWERING` | 重讲链轮次 +1 |
| 12 | `ANSWERING` | 重讲轮次达上限（4） | `RESUMING` | 记 `deferred`，承诺课末回来 |
| 13 | `ANSWERING` | 队列非空 | `ANSWERING` | 处理下一条（可先问"还有别的疑问吗"）|
| 14 | `RESUMING` | 三步重入播完 | `LECTURING` | 更新 `seg_index`；**清除 `resume_point`** |

### ⚠️ 结构性约束（最重要的一条）

> **`ANSWERING` 没有通向 `LECTURING` 的边。**
> 任何答疑都必须经过 `RESUMING`。这从图上排除了"答完就跑偏"——上课态由结构守住，而不是靠 Prompt 自觉。

```
ANSWERING ──✗──→ LECTURING      禁止直连
ANSWERING ──✓──→ RESUMING ──✓──→ LECTURING
```

## 3. 状态数据结构

```python
class ClassroomState(TypedDict):
    # 位置
    slide_index: int
    seg_index: int
    phase: Phase

    # 目标与进度
    session_goals: list[str]
    covered: list[Covered]              # 已讲台账,只增不改
    resume_point: Interrupt | None      # 让位点

    # 当前单元
    current_unit: LectureUnit
    unit_progress: float                # 已播到第几句

    # 提问
    pending_questions: list[Question]
    q_rounds: dict[str, int]            # {kp: 重讲轮次}
    deferred: list[str]                 # 暂放待回

    # 理解信号
    comprehension: dict[str, str]       # {unit_id: confirmed|vague|confused}
    probe_log: list[Probe]


class LectureUnit(TypedDict):
    unit_id: str
    slide: int
    index_in_slide: int
    text: str                           # 唯一事实源
    anchors: list[Anchor]
    reveal: list[str]
    pause: dict
    is_page_end: bool
    must_teach: bool
    kp: list[str]
    audio: list[AudioSeg]
    est_sec: float


class Anchor(TypedDict):
    element_id: str
    text_hint: str
    confidence: float


class Covered(TypedDict):
    kp: str
    slide: int
    unit_id: str
    covered_at: str


class Question(TypedDict):
    raw: str
    kind: str          # clarify|recall|forward|meta|emotion
    at_unit: str       # 提问时正在播的单元 —— 稀疏输入可被理解的根本
    status: str        # queued|answering|answered|deferred
    answer: str | None


class Interrupt(TypedDict):
    at_unit: str
    at_sentence: int
    sentence_complete: bool
    question: str
```

## 4. 事件接口

```python
def on_user_input(state, text): ...   # 学生任何输入的唯一入口
def on_unit_finished(state): ...      # 当前讲解单元播完
def on_audio_finished(state): ...     # 当前语音片段播完
def on_probe_timeout(state): ...      # 探针等待窗口超时
def on_user_command(state, cmd): ...  # 上一页/下一页/重复本页
```

### ⚠️ 播放完成事件必须带段序号（现场踩出来的坑）
`on_audio_finished` 不能只表示"某一段播完了"，必须带上**是哪一段**：

```
segment_start(seq) → audio_delta(seq) → segment_end(seq)
      → [前端真的播完] → speech_done(seq) → on_audio_finished(seq)
```

理由：状态转移全靠这个事件。只要有一次错配——上一段的 `speech_done` 晚到、落在这一段上，
或者某段根本没回——状态机就会把"播完了"记到**错误的段落**上，然后卡在原地**复读同一句话**
（实测：回执在 12 秒内被重复播了 41 次）。序号不匹配时**不算播完**，等自己的那一个。

同理，TTS 降级（没有音频）时必须自己按估算时长收尾再发 `speech_done`，
否则"等播完"会永远等下去 —— 这是同一个坑的另一面。

**⚠ 等之前先清信号，别等之后再清。** 等待用的那个事件要在发 `segment_start`
**之前**清空；如果放在发完 `segment_end` 之后清，客户端"一收到 `segment_start`
就回 done"的那次信号会被当场抹掉 → 误报"播放等待超时"，而且同一段会被重播好几遍
（实测见过一段回答连播 4 轮）。收到**别的段**的信号也不能直接放弃等待，
应当记为错配、清掉、继续等属于自己的那一个。

**⚠ 这一段到底"有没有声音"，判据是音频字节数，不是字幕文本。**
实测踩过一个静默故障：0 字节的音频被当成合成成功发出去，学生只看到字幕、
完全听不到声音，而控制台、页面、几个端到端脚本全都不报错 ——
因为那些脚本只读文本。所以：

- 合成要**先写临时文件、校验非空、再原子改名**，让最终缓存路径里只可能出现完整文件；
- 缓存命中也要**校验大小**，0 字节一律删掉重合成；
- 失败要留下原因并让调用方看得见，不能 `except: pass`。

### `on_user_input` 的分发规则

```python
def on_user_input(state, text):
    # I3:任何输入先回执,再处理
    play(PREBUILT["ack"])                       # < 300ms

    q = mk_question(text, state, status="queued")
    # mk_question 内部:at_unit = state.current_unit.unit_id
    #                        if state.phase == LECTURING else 最近已讲单元

    if state.phase == Phase.ANSWERING:
        # 不打断当前回答,只入队
        state.pending_questions.append(q)
        return state

    if state.phase in (Phase.ACKNOWLEDGING, Phase.YIELDING, Phase.RESUMING):
        state.pending_questions.append(q)
        return state

    if state.phase == Phase.PAUSING:
        close_probe_window(state, result="interrupted")
        state.pending_questions.append(q)
        return to(state, Phase.YIELDING)

    # LECTURING:继续讲完当前单元,由 on_unit_finished 触发让位
    state.pending_questions.append(q)
    return state
```

> 注意 `LECTURING` 分支**不改变 phase**——这正是"讲完这一段再答"的实现：学生输入只入队，单元播完时才在 `on_unit_finished` 里走向 `YIELDING`。

### 翻页指令单独处理（不走 `on_user_input`）

```python
def on_user_command(state, cmd):
    if cmd == "next":                       # 语义:我懂了,继续
        mark_skipped_unconfirmed(state)     # 未确认 must_teach → deferred(不静默丢弃)
        state.user_advanced = True
        advance_slide(state)
    elif cmd == "prev":                     # 语义:我没懂 → 重讲信号
        goto_slide(state, state.slide_index - 1)
        reset_probe(state, state.slide_index)
        enter_rephrase_round(state)         # 重讲链第 1 轮:换说法
        # covered 台账不删除(I6)
    elif cmd == "repeat":
        replay_units(state)
    return to(state, Phase.LECTURING)
```

### `on_unit_finished` 的核心分支

```python
def on_unit_finished(state):
    mark_covered(state, state.current_unit)     # 台账只增不改

    if state.pending_questions:                 # 队列非空 → 让位
        state.resume_point = mk_interrupt(state)
        return to(state, Phase.YIELDING)

    if state.current_unit.is_page_end:          # 页尾 → 探针
        open_probe_window(state)
        return to(state, Phase.PAUSING)

    advance_seg(state)
    return to(state, Phase.LECTURING)
```

## 5. 不变量（验收清单）

| 编号 | 不变量 | 违反后果 |
|---|---|---|
| I1 | 任何状态**不丢任何学生输入**——每条最终要么被解答、要么被明确暂放 | 课堂失信 |
| I2 | 除 `LECTURING` / `PAUSING` / 三个话术态外，不播放讲解语音 | 语音与状态不符 |
| I3 | 学生输入到达时**先回执**再处理 | 学生以为没人理 |
| I4 | **不硬切音频**：所有让位都发生在单元边界 | 体验廉价 |
| I5 | 答疑结束**必须经 `RESUMING`** 才能回到 `LECTURING` | 上课态丢失 |
| I6 | `covered` 台账只增不改 | 指代错乱、重复讲解 |
| I7 | `must_teach` 单元未播完，禁止自动翻页 | 内容漏讲 |
| I8 | 自动翻页必须同时满足"讲完了"与"听懂确认" | 翻页退化为计时器 |

## 6. 提问分流枚举

```python
class QKind(str, Enum):
    CLARIFY = "clarify"    # 这里没懂 / 再说一遍      → answer_inline    不打断主线
    RECALL  = "recall"     # 刚才第3页那个公式        → backtrack_page   切页再答
    FORWARD = "forward"    # 那二次函数呢 / 会考吗     → hook / 划界
    META    = "meta"       # 学这个有啥用 / 要不要背   → fixed_reply     固定话术
    EMOTION = "emotion"    # 好难啊 / 不想学了        → brief_empathy   先共情再拉回

class QAction(str, Enum):
    ANSWER_INLINE  = "answer_inline"
    BACKTRACK_PAGE = "backtrack_page"
    HOOK           = "hook"
    FIXED_REPLY    = "fixed_reply"
    BRIEF_EMPATHY  = "brief_empathy"
```

分流节点的输出必须结构化，**不让模型自由发挥**：

```python
{
  "kind": QKind,
  "action": QAction,
  "pause_lecture": bool,
  "backtrack_to_slide": int | None,
  "reason": str
}
```

## 7. 重讲链（"没听懂"应答）

| 轮次 | 策略 | 说明 |
|---|---|---|
| 1 | 换说法 | 换表达角度，**不是复读** |
| 2 | 举例子 / 类比 | 具体化 |
| 3 | 拆步骤 / 退前置 | 再切成更小的步子 |
| 4 | **暂放 + 承诺** | 记入 `deferred`，课末回来；**必须有，否则死循环** |

- 重讲粒度 = `Question.at_unit` 定位到的那一小块，**不是整页**
- 轮次在**换页或学生换话题**时重置（`q_rounds` 清空对应项）

### ⚠️ 轮次必须"每个作答周期只升一轮"

轮次要按**这个单元上真正开口重讲的次数**累计，不能按"方法被调用了几次"算。
一个作答周期（从让位到重入）里，生成可能被触发不止一次 —— 如果每次都升一轮，
学生点两下就把 4 轮上限烧完，而真正该给的两轮重讲根本没发生。

同理，**第 4 轮不调 LLM 也必须把周期标记为"已生成"**。否则下一轮
`next_speech` 会看到"还没生成过"又冲进来一次，变成活锁（实测能在一秒里空转几万次）。
而且第 4 轮之后学生再喊"没懂"仍要有话说（换成"已经排进待回看"的说法），
**绝不能原地重播同一句话**。

## 8. 翻页判定阻塞条件

```python
class Block(str, Enum):
    PENDING_QUESTIONS = "pending_questions"   # 队列非空
    ANSWERING         = "answering"           # 让位未结束
    JUST_CONFUSED     = "just_confused"       # 刚说没听懂 → 应重讲
    STEP_INCOMPLETE   = "step_incomplete"     # 页内分步未走完
    MUST_TEACH_LEFT   = "must_teach_left"     # 必讲点未讲全
```

自动翻页 = 门一（讲完了）∧ 门二（听懂 / 明确跳过 / 探针超时）∧ 无阻塞。
任一门不满足或存在阻塞 → **禁止自动翻页，但学生手动翻页始终可用**。

手动跳过的语义：未确认的 `must_teach` 知识点转入 `deferred`，**不静默丢弃**。

## 9. 实现时最常见的错误

| # | 错误做法 | 为什么错 |
|---|---|---|
| 1 | 学生提问时立刻暂停音频 | 硬切音频；段末让位被绕过了 |
| 2 | 答疑结束后直接回到 `LECTURING` | **上课态丢失**，AI 退化成答疑机器人 |
| 3 | 把整页当成一个讲解单元 | 让位延迟 = 整页时长（可达数分钟） |
| 4 | 翻页只看"讲完了" | 翻页退化成计时器，失去教学意义 |
| 5 | 把学生沉默记为"懂了" | 把噪声当掌握度证据 |
| 6 | 只预生成讲解音频，不留运行时生成通道 | 答疑与重入话术无音频可用 |
| 7 | 错答后的重讲仍是"重放同一段" | 学生说没懂 → 重复原话，明白度几乎不提升 |
| 8 | `speech_done` 不带段序号 | 一次错配就复读同一句（实测回执被播 41 次），状态机再也回不到主线 |
| 9 | 生成是串行的（过渡话术→分流→回答） | 让位延迟 20.3 秒；三步并行后 5.7 秒 |
| 10 | 等整段回答生成完才播第一句 | 过渡话术后静默空等（实测 15.9 秒），像课堂卡死 |
| 11 | 音频文件直接写最终路径、缓存命中不校验大小 | 进程在合成中途被杀就留下 0 字节文件；它会被**永久**当成"合成成功"发出去，学生只看到字幕、完全听不到声音，而全程不报错 |
| 12 | 只读字幕文本来判断"学生听到没有" | 实测过：几个端到端脚本都只读文本，打印"听到了：……"其实只证明字幕有字，**"没声音"这类故障全被漏掉**。判据必须是音频字节数 |
| 13 | TTS 失败写进一个永不失效的黑名单 | 一次网络抖动就让那句话整节课都没声音；服务恢复了它还是哑的。应当是"冷却后重试"，不是永久沉默 |
| 14 | 等 `speech_done` 之前才 `clear()` 事件 | 客户端一收到 `segment_start` 就可能回 done，那一瞬间会被 `clear()` 抹掉 → 误报"播放等待超时"、同一段被重播。**先清再发 `segment_start`**；收到别的段的信号也不该放弃等待，而应清掉、继续等这一段 |

> 第 11～14 条有一个共同点：**受害者是学生，而系统一声不吭**。
> 它们不影响状态机、不影响翻页、不影响指标，所以不会在"功能测试"里暴露。
> 对付这类故障的办法只有两个：让失败**可见**（说清原因，不吞异常），
> 以及让判据**落在真实边界上**（音频字节数，而不是字幕文本）。

## 10. 三个必须观测的指标

| 指标 | 含义 | 用途 |
|---|---|---|
| **让位延迟** | 学生提问 → 开始作答的间隔 | 段末让位方案的核心代价；直接反映讲解单元长度是否合理 |
| **归位成功率** | 让位后是否成功回到 `LECTURING` 且未漏讲 | I5 是否被真正遵守 |
| **探针响应率** | 探针发出后被回应的比例 | 判断探针是否值得保留（见主文档 V8） |

**实测基线**（本地 `ds-ins:latest` + edge-tts，模拟浏览器客户端）：
让位延迟单次实测 **4.7~13.2 秒**（p50 ≈ 6 秒，波动来自回答长度）；归位成功率 **100%**（9 项端到端检查全过）；
探针响应率 **0%**（3 页 3 次探针全部超时 → 记为 `vague`）。
探针这一项正是 V8 要诚实面对的地方：原型阶段它一次也没换来"确认听懂"。
