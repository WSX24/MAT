# 课堂交互设计（个人自学场景）

> **适用范围**：课堂子系统的设计基线 —— `TeachingFlow/classroom/` 就是按这份设计做的实现。
> **目标场景**：个人自学。课堂中只有两个人——**学生 + AI 教师**。
> **交互模型**：让位式（教师主讲，学生提问则教师让位，答完归位继续）。
> **响应拓扑**：段末让位（讲完当前讲解单元再答，不硬切音频）。
>
> 本文档是课堂交互方向的**唯一完整设计**，覆盖状态机、讲解单元与锚定、打断与让位、提问分流、重讲链、翻页判定、节奏与理解探针、技术约束。
> 配套速查：[`课堂状态机规范.md`](课堂状态机规范.md)（本文档第 3 章的可实现精简版）。

---

## 0. 文档定位

### 0.1 这份文档解决什么

不是"怎么调用 LLM 讲课"，而是**一次课堂是怎么进行的**。核心是一台显式的状态机——这是当前设计中最缺、也决定成败的一层。

**一句话**：AI 老师"能不能讲好"是模型能力问题；"有没有在上课"是状态机问题。后者才需要设计。

### 0.2 与既有文档的关系

- 本文档按**当前设计**（PPT 为主体、教师 Agent 上课）编写，不沿用既有流程假设。
- 依赖的上游产物：**PPT 课件**、**与课件匹配的课程大纲**。
- 涉及但不在本文档范围内：Agent 间通信协议、课后闭环、多 Agent 分工——这些属于项目其他部分，本文档不做规定。

### 0.3 四个已定的前提

| 编号 | 前提 | 对设计的影响 |
|---|---|---|
| P1 | **个人自学**，课堂里只有学生和 AI 教师 | 无并发、无发言人调度、无课堂纪律；可以把全部预算花在单链路的体验上 |
| P2 | **让位式**，不是边讲边聊 | 主讲线必须始终存在；教师身份要能被状态机守住 |
| P3 | **段末让位**：讲完当前讲解单元再答 | 不需要处理音频硬切、半句续接；代价是**讲解单元长度成为核心设计变量**（见 §2.3） |
| P4 | **教师 Agent 负责上课** | 讲课、答疑、判节奏、翻页是同一个角色的不同状态，不是多角色协商 |

### 0.4 设计原则

1. **状态驱动，不是 Prompt 驱动**：能写成状态转移的，不写进 Prompt。
2. **确定性优先**：翻页、探针触发这类判定能规则的不用模型，模型只在灰区提建议。
3. **学生的沉默不等于理解**：所有理解信号都由系统主动探测获得，不依赖学生主动汇报。
4. **承认学生不肯打字**：交互设计的前提是"学生只会打 3~5 个字"。
5. **打断是常态，不是异常**：让位与归位是主循环的一部分，不是错误处理分支。

## 1. 交互模型

### 1.1 为什么是让位式

| | 边讲边聊 | **让位式（选定）** |
|---|---|---|
| 形态 | 教师与学生一人一句，像聊天 | 教师照主线讲，学生提问则教师让位，答完归位 |
| 主讲线 | 会被对话冲散，逐渐退化成答疑机器人 | 始终存在、可观测、可恢复 |
| 学生感受 | "在和 AI 聊天" | "在上课，我可以举手" |
| 本质 | 对话系统 | **课堂** |

**参照目标是课堂，所以必须让位式。** 一旦选定，真正的难点就从"怎么答"转移到**"怎么归位"**——本文档 §4 的全部篇幅都在处理这件事。

### 1.2 段末让位：本设计最关键的决策

学生提问时，音频**不立即截断**，而是：

```
学生提交问题
   ↓ ① 立即回执("收到,老师马上就到")
   ↓ ② 教师继续讲完当前讲解单元
   ↓ ③ 在单元边界让位 —— 用一句过渡话术接住
   ↓ ④ 回答问题
   ↓ ⑤ 三步重入,回到被打断的位置继续
```

**换来的三个好处**（这正是选它的理由）：

1. **音频永远在句/段边界停下** —— 不需要处理硬切、淡出、半句截断
2. **学生永远能听完完整的句子** —— 不会出现"AI 讲了半句学生没听到，后面全崩"
3. **让位点天然有语义边界** —— 归位时"刚才说到哪"永远明确

**必须付的代价**（必须正视，不能只讲好处）：

- **响应延迟**：学生要等当前单元讲完。若单元 60 秒，学生等 60 秒会觉得被无视。
- 因此产生了硬约束 👉 **讲解单元必须短**（§2.3）。

### 1.3 反过来说：这三个问题被消掉了

以下原本是语音课堂最难的地方，因为段末让位而**不需要设计**：

- 音频打断与淡出的体验优化
- 讲解断点精确到分句的续接
- "被打断的意思说完了吗"的判定

**这不是省事，是设计上的正确取舍**：把一个高频但不可控的问题，换成一个低频且可控的设计变量。

## 2. 讲解单元（LectureUnit）

### 2.1 为什么是这个粒度

"PPT 的页"和"讲课的单元"**不是 1:1**。一页里可能塞 3 个知识点，也可能只有一张图要讲 2 分钟。所以必须引入一个独立于"页"的粒度：

**讲解单元 = 教师一口气讲完的一段完整表达，是让位、音频、锚定、探针的共同单位。**

它是本设计里最重要的数据结构——**所有交互机制都挂在它身上**：

| 机制 | 依赖讲解单元的哪一部分 |
|---|---|
| 段末让位 | 单元的**边界**（让位只发生在边界） |
| 锚定高亮 | 单元的 `anchors`（讲到哪、高亮哪） |
| 分步显示 | 单元的 `reveal`（视觉进度与听觉同步） |
| 理解探针 | 单元的 `is_page_end`（探针只在收尾单元后触发） |
| 翻页判定 | 单元的 `must_teach`（必讲点讲全了没） |
| 重讲链 | 单元的 `kp`（卡住的是哪个点） |

### 2.2 数据结构

```python
class LectureUnit:
    unit_id: str            # 全局唯一,如 "S12-U02"
    slide: int              # 所属页
    index_in_slide: int     # 页内第几个单元
    text: str               # 讲解正文(唯一事实源:朗读/字幕/台账都取自它)

    # ---- 锚定(§2.4)----
    anchors: list[Anchor]   # 讲这段话时,页面上应高亮什么

    # ---- 视觉与语音节奏 ----
    reveal: list[str]       # 本单元首次讲到时才显示的元素 id(分步)
    pause: dict             # {"after_sentence": 2, "sec": 1.5} 句内留白
    is_page_end: bool       # 是否是本页的收尾单元(探针与翻页的触发点)

    # ---- 教学约束 ----
    must_teach: bool        # 是否必讲(翻页判定的输入)
    kp: list[str]           # 涉及知识点 id(台账、重讲、后续扩展都用它)

    # ---- 语音(§5.4)----
    audio: list[AudioSeg]   # 按句切分,每句独立音频片段
    est_sec: float          # 预计时长(节奏控制与延迟预算用)
```

### 2.3 长度的硬约束（本设计的关键参数）

因为段末让位，**学生的最坏等待时间 = 当前单元的剩余时长**。所以：

| 参数 | 建议值 | 理由 |
|---|---|---|
| 单元正文 | **80~180 字**（约 15~30 秒语音） | 等待可接受 |
| **硬上限** | **约 45 秒**（≈250 字） | 超过这个长度，学生等完已经忘了要问什么 |
| 单元下限 | 约 8 秒 | 太碎会让 AI 显得急躁，也让过渡话术过密 |

**这不是美学问题，是体验的硬门槛。** 生成脚本时必须做长度校验，超限就拆分。

> ⚠️ **建议把"最大等待时长"设为可配置项并实测**。它同时影响单元长度建议、探针等待窗口、以及学生对"老师有没有在理我"的主观判断。见 §6。

### 2.4 锚定系统：让"讲"和"看"对上

**问题**：课件上的信息大部分是空间性的（图表、公式、"左边这个"），而讲解是时间性的语音流。真实课堂里老师靠**指**来搭桥；AI 说不出"这里"，**因为它不知道"这里"是哪**。

**这会导致什么**：AI 只能念页面文字；或者更糟——说"大家看这个图"，而屏上有三张图，学生不知道指哪张。

**解法：每个讲解单元显式声明它指向页面上的什么。**

```python
class Anchor:
    element_id: str      # 指向 slide.elements 中的元素
    text_hint: str       # 该元素的文本摘要(供生成与审核时人眼校验)
    confidence: float    # 锚定置信度;过低则前端退化为"整页高亮"
```

**前端行为**：语音播放到某句 → 对应元素**高亮**；`reveal` 中的元素**此时才出现**（分步推进）；字幕与语音**逐字一致**。

**生成侧要求**：教师 Agent 产出的不是纯文本，而是带 `anchors` 的结构化输出。做法可以很轻——**在讲解文本里用占位符标注，落库时解析**：

```
"我们看[#formula_delta]这个判别式[/#],它决定了根的情况。"
```

### 2.5 课件来源决定锚定成本（重要提醒）

| 来源 | 锚点可得性 | 说明 |
|---|---|---|
| **系统生成课件** | ✅ 解析成本≈0 | 元素是程序生成的，id 天然存在，`reveal` 顺序也可提前规划 |
| **教师上传用户 PPT** | ⚠️ 需提取，且会走形 | 从形状层级提取文本/图形分组生成 id；图片、图表、公式**无法定位到子元素**，只能整块锚；版式与动画时序拿不到 |
| **教师上传 PPT + 前端重绘** | ✅ 可控 | 需自己渲染，但能拿到完整的元素级控制力 |

**结论**：若要锚定效果稳定，**优先系统生成课件**；若必须支持任意上传 PPT，需接受"锚点粒度变粗 + 页内分步受限"，并据此降低 §2.4 的预期。

### 2.6 讲解话术要贴近课件措辞

一个容易被忽略的连带约束：

**如果讲解文本和页面文字对不上，锚定就失效。** 页上写"判别式"，语音说"那个 b²-4ac 的式子"——学生找不到。

所以生成讲解时要求：**术语、符号、标题的措辞与课件保持一致**。这不是让讲解变死板，而是要求"术语一致 + 指引明确"。

### 2.7 单元的可审核性

课件 + 脚本是**课堂的输入**，它们错了，后面全套机制都会忠实地讲错。所以需要最小的人工审核面：

- 按页列出：本页有几个单元、每单元对应哪些锚点、预计时长、是否 `must_teach`
- 校验项：单元总时长 vs 计划课时；`must_teach` 的知识点是否都在大纲内
- **低置信度锚点必须显式标出**，供人快速剔除

## 3. 状态机

### 3.1 "上课态"必须被固定下来（本节是重点）

**现象**：AI 老师被提问几次之后，会不知不觉丢掉教师身份，退化成答疑工具。不再有"这节课要教会你什么"的目标感，变成"你问什么我答什么"。这是让位式课堂最典型、也最难自纠的失败模式。

**根因**：如果把"当前页的文字描述"单独喂给教师 Agent，这是**局部视角**——它知道这一页有什么，但不知道这节课要到哪、已经走到哪、离目标还有多远。**没有全局目标牵引的状态机，必然被局部输入牵着走。**

**固定方式：四道约束，全部落在状态上，不靠模型自觉。**

| 编号 | 约束 | 落地方式 |
|---|---|---|
| **C1** | 课堂必须有显式目标 | `session_goals`（1~3 条，形如"能判断 Δ 的符号对根的影响"，**不是"讲完 15 页"**）；每页声明自己为哪个目标服务 |
| **C2** | 位置与进度必须显式可查 | `slide_index` / `seg_index` / `covered[]` 台账（§3.3） |
| **C3** | 让位不改变主讲线的存在 | 状态机里 `LECTURING` 是**默认态**，其他态都是它的临时让位；只有经过 `RESUMING` 才能回到 `LECTURING`，**没有直接路径** |
| **C4** | 打断必须被记录并归位 | 学生打断时记录"让位点"；答疑结束后**必须**归位，不允许就此进入自由对话 |

**唯一的验收判据**：

> 学生连问 5 个问题后，AI 还能在第 6 轮主动说："好——我们回到刚才那里，继续。"

**说得出，状态机就守住了；说不出，就说明已经丢掉上课态，无论 Prompt 里写了多少遍"你是老师"。**

这一条应该写进系统提示，**同时**由状态机强制（C3 的结构性保证），两者缺一不可。

### 3.2 状态定义

| 状态 | 含义 | 是否播放语音 | 可被学生输入打断 |
|---|---|---|---|
| `LECTURING` | 正常讲课，播放讲解单元 | ✅ | ✅ |
| `PAUSING` | 主动停顿/探针等待，学生思考中 | ⏸ 可播探针话术 | ✅（**这正是它存在的意义**） |
| `ACKNOWLEDGING` | 已收到提问，播回执话术 | ✅ 短话术 | ❌ |
| `YIELDING` | 讲完当前单元，播过渡话术，准备让位 | ✅ 短话术 | ❌ |
| `REDIRECTING` | 回顾型问题：切页/定位，再作答 | ⏸ 可视情况 | ❌ |
| `ANSWERING` | 回答学生提问（段末让位已生效） | ✅ | ⚠️ **只入队，不打断**（§4.5） |
| `RESUMING` | 三步重入，回到被打断的位置 | ✅ 含生成话术 | ❌ |

**状态唯一**：同一时刻只有一个状态，用一个字段存。不做并行状态——个人自学场景没有并发的必要，而唯一状态让"老师现在在干什么"永远可答。

### 3.3 状态数据结构

```python
class ClassroomState:
    # ---- 位置 ----
    slide_index: int
    seg_index: int                  # 当前页第几个讲解单元
    phase: str                      # 上表 7 个状态之一

    # ---- 课堂目标与进度(C1 / C2 / 问题六的台账)----
    session_goals: list[str]        # 这节课要教会什么
    covered: list[Covered]          # 已讲台账(见下)
    resume_point: Interrupt | None  # 让位点:被打断时记下,归位时用

    # ---- 当前单元 ----
    current_unit: LectureUnit
    unit_progress: float            # 当前单元已播到第几句(用于切分续讲)

    # ---- 提问(§4)----
    pending_questions: list[Question]   # 待处理队列(段末让位期间到达的)
    q_rounds: dict                      # {kp: 本轮"没听懂"重讲轮次}
    deferred: list[str]                 # 暂放待回的问题(§4.7 第 4 轮)

    # ---- 理解信号(§6)----
    comprehension: dict             # {unit_id: confirmed | vague | confused}
    probe_log: list[Probe]          # 探针发出与响应记录


class Covered:                      # 已讲台账
    kp: str
    slide: int
    unit_id: str
    covered_at: str                 # 时间戳(用于解析"刚才")


class Question:
    raw: str                        # 学生原文(极短,如"没听懂")
    kind: str                       # §4.2 的五类
    at_unit: str                    # 归属:提问时正在讲哪个单元(§4.3 的核心)
    status: str                     # queued | answering | answered | deferred
    answer: str | None
```

**关于 `covered` 台账**（对应"长课堂会重复讲"的问题）：

- 它是**防重复**的依据（AI 不会把第 5 页讲过的东西在第 11 页当新内容重讲）
- 它是**真实指代**的依据（AI 说"我们前面提过"时，有据可查，不再编造）
- 它是**翻页判定**的输入（本页必讲点讲全了没）
- 它把"刚才"变成**可解析的坐标**（§4.4）

### 3.4 状态转移表

| 当前 | 触发 | 下一个 | 动作 |
|---|---|---|---|
| — | 课堂开始 | `LECTURING` | 载入目标与第 1 页；播首个单元 |
| `LECTURING` | 当前单元播完，非页尾 | `LECTURING` | 播下一单元 |
| `LECTURING` | 当前单元播完，且 `is_page_end` | `PAUSING` | 播探针话术，进入等待窗口（§6.3） |
| `LECTURING` | **收到学生输入** | `LECTURING` | ① 立即回执；② 入队 `pending_questions`；③ **继续讲完当前单元** |
| `LECTURING` | **收到翻页指令（显式控制权）** | `LECTURING` | 立即执行；记 `user_advanced`；未确认项转 `deferred`（§5.5） |
| `LECTURING` | 当前单元播完，且队列非空 | `YIELDING` | 播过渡话术，让位 |
| `PAUSING` | 窗口内收到输入 | `YIELDING` | 关闭窗口，播过渡话术 |
| `PAUSING` | 窗口超时无输入 | `LECTURING` | 记 `vague`；推进（**必须保留事后回退入口**） |
| `YIELDING` | 过渡话术播完 | `REDIRECTING` / `ANSWERING` | 按 `qkind` 分流（§4.2） |
| `REDIRECTING` | 切页/定位完成 | `ANSWERING` | 开始作答 |
| `ANSWERING` | 答案播完，学生满意 | `RESUMING` | 三步重入 |
| `ANSWERING` | 学生说"没听懂" | `ANSWERING` | 进入重讲链，轮次 +1（§4.7） |
| `ANSWERING` | 重讲轮次达上限 | `RESUMING` | 记 `deferred`，承诺回来时再讲 |
| `RESUMING` | 三步重入播完 | `LECTURING` | 更新 `seg_index`；**清除 `resume_point`** |

**结构性的保证**：`ANSWERING` **没有**通向 `LECTURING` 的边。任何答疑都必须经过 `RESUMING`——这就是 C3 的硬保证，从图上就不可能"答完就跑偏"。

### 3.5 不变量（实现时的验收清单）

| 编号 | 不变量 | 违反后果 |
|---|---|---|
| I1 | 任何状态**不丢任何学生输入**——每条输入最终要么被解答、要么被明确暂放 | 学生提问石沉大海，课堂失信 |
| I2 | 除 `LECTURING` / `PAUSING` / 三个话术态外，**不播放讲解语音** | 语音与状态不符，学生困惑 |
| I3 | 学生输入到达时，**先回执**再处理 | 学生以为没人理，重复提问 |
| I4 | **不硬切音频**：所有让位都发生在单元边界 | 体验廉价感 |
| I5 | 答疑结束必须经 `RESUMING` 才能回到 `LECTURING` | **上课态丢失**（§3.1） |
| I6 | `covered` 台账只增不改 | 指代错乱、重复讲解 |
| I7 | `must_teach` 单元未播完，**禁止自动翻页** | 内容漏讲 |
| I8 | 自动翻页必须同时满足"讲完了"与"听懂确认" | 翻页判定退化为计时器 |

## 4. 交互运行时

### 4.1 主循环

```
┌─ LECTURING ─────────────────────────────────────────┐
│  播讲解单元(语音 + 字幕 + 锚点高亮 + 分步显示)         │
│         │                                            │
│         ├─ 学生输入 ──→ 回执 + 入队 ──┐               │
│         │                              │(不中断)      │
│         └─ 单元播完 ◀──────────────────┘               │
└─────────────┬────────────────────────────────────────┘
              │
      ┌───────┴────────┐
      │                │
  页尾单元          普通单元
      │                │
      ▼                ▼
  ┌────────┐     队列空?
  │PAUSING │        │
  │ 探针等待 │     ├─是─→ 下一个单元 (LECTURING)
  └───┬────┘        └─否─→ YIELDING
      │
      ├─ 有输入 ─→ YIELDING
      └─ 超时 ──→ 记 vague,下一个单元

  ┌──────────┐   过渡话术   ┌────────────┐
  │ YIELDING │ ──────────→ │ 按类型分流  │
  └──────────┘             └──────┬─────┘
                                  │
              ┌───────────────────┼───────────────────┐
              ▼                   ▼                   ▼
        REDIRECTING          ANSWERING          (情绪/元问题)
        切页/定位              作答                短回应
              │                   │                   │
              └─────────┬─────────┴───────────────────┘
                        ▼
                   ┌──────────┐  三步重入   ┌───────────┐
                   │ RESUMING │ ─────────→ │ LECTURING │
                   └──────────┘             └───────────┘
```

### 4.2 提问分流

**为什么必须分流**：如果每种提问都暂停讲课，主讲线必被冲散（§3.1）。而且学生表达经常不完整，需要结合上下文推断意图。

```python
# 分流节点的输出(结构化,不让模型自由发挥)
{
  "kind": "clarify | recall | forward | meta | emotion",
  "action": "pause_and_answer | backtrack_page | hook | fixed_reply | brief_empathy",
  "pause_lecture": True,
  "backtrack_to_slide": None,     # recall 时使用
  "reason": "..."
}
```

| 类别 | 例子 | 处理 |
|---|---|---|
| `clarify` 澄清型 | "这里没懂""再说一遍" | 原地简短解答 → 归位继续，**不打断主线** |
| `recall` 回顾型 | "刚才第 3 页那个公式为什么成立" | 教师**显式切回那一页**（视觉也回去）再讲 → 归位 |
| `forward` 前瞻型 | "那二次函数呢""这个会考吗" | 判断是否已讲到：没讲到 → **埋钩子**"这个我马上要讲"；超纲 → 明确划界 |
| `meta` 元问题型 | "学这个有什么用""要不要背" | **固定话术策略**，不展开分析，不逃到泛泛而谈 |
| `emotion` 情绪型 | "好难啊""不想学了""今天好累" | **先简短共情，再拉回**——不走知识答疑路径（见下） |

**情绪型必须单独处理。** 这是自学场景里最关键的一类输入：它不是提问，但必须被接住。学生说"好难""不想学了"，机械地继续讲知识，是 AI 老师最像机器人的时刻。

**做法**：简短共情（一两句）+ 给一个**降低门槛的下一步**（"这块确实难，我们先把最简单的那个情况过一下"），然后继续。若情绪信号强烈且反复出现，插入"要不要先休息一下"的选项。

### 4.3 稀疏输入：只有三个字怎么办

**这是整个交互里最尖锐的矛盾：输入带宽远小于输出带宽。**

AI 老师说 60 秒（200 字），学生只肯打 3 个字："没听懂"。而这三个字**信息量几乎为零**——是概念不懂？某一步不懂？还是没跟上？**但 AI 必须靠它决定下一步。**

**三层解决：**

**① 系统补足上下文（主要手段）**

发挥自学场景独有的优势：**系统知道课堂进行到哪里**。把打断点上下文拼进分流与答疑的 Prompt：

- 正在讲哪个单元的哪一句
- 刚讲过的单元（前 1~2 个）
- 当前页的锚点列表与 `kp`
- 课堂目标

于是"没听懂"可以被**自动归属到刚刚发生的那一两句**，而不是重讲整页。

```python
Question.at_unit   # 学生提问时正在播的单元 —— 这条归属信息是稀疏输入能被理解的根本
```

**② 学生侧减负：把"我不懂哪里"变成点一下**

- **快捷反馈条**（针对打断，第二优先做）：`没听懂 / 举个例 / 说慢点 / 继续`
- **一个"不懂"按钮**：点击即归属到当前单元，学生不用组织语言
- **课末票选"最没懂的一页"**：收集定位信息，比让学生打字高效得多

**③ 承认两类提问，交互形态不同**

| 类型 | 特征 | 交互形态 | 优先级 |
|---|---|---|---|
| **打断式**（高频） | 短、即时、随讲随出 | 快捷短语 + 按钮；AI 靠上下文补全 | **P0** |
| **输入式**（低频） | 长、需组织语言、问的是真问题 | 自由文本框 | P1 |

### 4.4 指代解析："刚才那一步"

学生最常用的说法是"**刚才那一步为什么**""**上面那个公式**"。系统必须把它翻译成明确坐标。

**两类线索：**

| 线索类型 | 例子 | 解析方式 |
|---|---|---|
| 时间性 | 刚才、刚刚、上面、前面 | 按 `covered` 时间序回溯匹配 |
| 内容性 | "那个公式""判别式" | 与单元的 `anchors.text_hint` / `kp` 匹配 |

**解析流程**：从最近往前扫 → 候选打分 → 唯一高分则定；有歧义交给 LLM 裁定；仍不确定则**列 2~3 个候选让点选**。

⚠️ **歧义消解的预算**：不要每次都反问"你说的是哪里？"——**每反问一次，课堂就断一次**。单节课内反问答次数的上限应该是可配置的，超出后用"最近单元"作为默认兜底。

### 4.5 段末让位期间的新输入

学生在 `ANSWERING` 期间又提问（追问或换话题）：

- **全部入队，不打断当前回答** —— 这是"讲完这一段再答"原则的一致性延伸：回答也应当被完整听完
- 队列按到达顺序处理
- 学生自己说"懂了""没事了" → **自动关闭**对应的待处理问题
- 一个问题答完，教师主动问"还有别的疑问吗？"——**这不是客套，是清空队列的机会**，避免频繁在讲课与答疑之间来回切换
- 队列清空后才进 `RESUMING`

### 4.6 三步重入（归位）

**核心认识：被回答问题后，学生已经断片了。** 直接说"我们继续"是无效的。

```
认知层  "好——你问的这个地方,其实和我们现在讲的是一件事。"
        (作用:让学生知道刚才的插曲已经结束,并把他的问题接回主线)
定位层  "我们刚才说到判别式的符号,也就是这一页第二行。"
        (作用:重建位置感;配合锚点高亮,视觉上"跳回原处")
续接层  (回到被打断的原文,或补完被打断的意思)
        (作用:继续上课)
```

**关键约束：**

1. **第 1、2 层是运行时生成的，不在预生成脚本里。** 所以脚本方案**必须为"重入话术"预留生成位**——否则会出现"重入话术缺失，AI 直接跳到下一页"。
2. 若单元在被打断时**已播到后半段**，续接层**不要重播整个单元**——从被打断的句子继续，把原单元当作已讲部分记账。
3. 若被打断的那个意思**没说完**，续接层先补完，再往下讲。
4. 若答疑时学生要求**切回过某页**，归位需要先切回当前页（视觉切换 + 一句"我们回到刚才那里"），再进续接层。

### 4.7 "没听懂"应答：重讲链

**学生说没听懂时，最自然的反应是"那我再说一遍"——而这是最差的做法。** 同样的话讲第二遍，理解率提升极有限，学生更快放弃。

真实老师的动作是：**换角度、举例子、拆更小、退到前置。**

| 轮次 | 策略 | 话术要点 |
|---|---|---|
| 1 | **换说法** | 换表达角度，不是复读 |
| 2 | **举例子 / 类比** | 具体化 |
| 3 | **拆步骤 / 退前置** | 把这块再切成更小的步子 |
| 4 | **暂放 + 承诺** | "这个点确实绕，我们先把后面讲完，最后回到这里" |

**关键设计：**

- **重讲的粒度是"卡住的那一小块"**，不是整页。由 `Question.at_unit` 提供定位。
- **第 4 轮的"允许暂放"必须存在**——否则会陷入"不懂→重讲→还不懂→再重讲"的死循环，一页卡 10 分钟。上限也是课堂节奏的保护。
- **暂放要"可视化待办"**：记入 `deferred`，在课末（或翻页前）回看。**只承诺不兑现比不承诺更伤信任。**
- 轮次计数在**换页或学生换话题**时重置。

### 4.8 等待与探针（对应"沉默是教学工具"）

**你的设计里原本没有"停顿"这个概念**：讲解 → 播放 → 输入 → 翻页，全程没有一处是教师主动停下等学生。但真实课堂里，"这个地方大家想一下"然后安静三秒，是**信息处理效率最高的时刻**。一直讲的课不叫课，叫有声书。

**更重要的是：停顿是 AI 获得反馈的唯一窗口。** 反馈只来自"学生主动打字"是不够的——大部分学生听不懂时**不会主动说**，他们会沉默、走神、关掉页面。

**三种停顿：**

| 类型 | 触发 | 时长 | 是否等待输入 |
|---|---|---|---|
| **呼吸停顿** | 单元内 `pause` 标记的句后 | 1.5~3 秒 | ❌ 自然留白 |
| **理解探针** | 页尾单元（`is_page_end`）之后 | 等待窗口 | ✅ 进入 `PAUSING` |
| **复述式探针** | 关键概念后（低频） | 等待窗口 | ✅ **信号价值最高**，但最费时间 |

**探针话术要轻**："到这里清楚吗？"——这不是客套，是**低成本的探针**。学生回"嗯"或干脆不回，都是信号。

**等待窗口的规则：**

1. 必须**有窗口**：超时无响应则继续（否则课堂无法推进）
2. 必须**保留回退入口**：超时不是"关掉这个点"，学生事后仍可问，且能被正确归属到那一页
3. **必须可被打断**：`PAUSING` 期间任何输入都有效——**这正是它存在的意义**
4. **要有 UI 提示**：否则学生分不清"卡住了"还是"在等我"
5. **不能把探针变成打断的节拍器**：探针应按**页级 / 知识块**布点，不是每个单元后都问，否则会把课堂切碎

**关于"默认画像"的风险提醒**：若把沉默一律记为"模糊"，等于在画像里给所有学生记了一堆噪声。**沉默的真实含义可能是"懂但懒得回""其实没在听""在思考"**——这三者无法区分。所以 `vague` 只能作为弱信号、不能作为掌握度证据，这与"不要用学生是否配合来判断理解"是同一件事（§1.4 原则 3）。

## 5. 翻页判定

### 5.1 设计原则

**翻页判定不是"计时器"，也不该由 LLM 自由裁量。**

- LLM 自由判断的风险：节奏不可控、演示不可复现、打断后状态不一致、出错无法归因
- 采用的三层结构：**规则层（决定性）→ 灰区咨询 LLM → 状态机裁决**
- LLM 只提建议，**必须过规则校验**：规则明确禁止时，不听 LLM 的

这与"客观题判分必须 100% 确定、可复现"是同一种工程判断：**能规则的不用模型。**

### 5.2 双门判定：讲完了 + 听懂了

**这是本设计对翻页最重要的修正。**

```
自动翻页条件 =
   门一:讲完了      ∧   门二:听懂了(或明确跳过)   ∧   无阻塞
```

- **门一（讲完了）**：本页全部单元已播完；`must_teach` 的知识点均已在 `covered` 中；页内 `reveal` 分步已全部展开
- **门二（听懂了）**：页尾探针结果为 `confirmed`，**或**学生手动推进（= 显式跳过），**或**探针超时后继续
  - ⚠️ 注意门二不能要求 `confirmed`——否则学生不回应就永远翻不了页。超时继续是允许的，但要**记入弱信号**并在 UI 上留回退入口

### 5.3 阻塞条件（任一成立，禁止自动翻页；手动仍可用）

| 阻塞 | 说明 |
|---|---|
| 有人正在提问 / `ANSWERING` 中 | 让位未结束 |
| `pending_questions` 非空 | 队列未清 |
| 刚说"没听懂" | **应优先重讲，而不是翻页** |
| 页内分步未走完 | 视觉与听觉不同步 |

### 5.4 规则层伪码

```python
def can_auto_advance(state) -> bool:
    page = script[state.slide_index]

    # 门一:讲完了
    if any(u.must_teach and u.unit_id not in covered_ids(state)
           for u in page.units):
        return False
    if not page.all_revealed(state):
        return False

    # 阻塞
    if state.phase in (ACKNOWLEDGING, YIELDING, ANSWERING, RESUMING):
        return False
    if state.pending_questions:
        return False
    if state.comprehension.get(page.probe_unit) == "confused":
        return False            # 应重讲,不是翻页

    # 门二:听懂或明确跳过 或 探针已超时
    probe = state.probe_log.last(page)
    if probe and probe.result in ("confirmed", "timeout"):
        return True
    if state.user_advanced:     # 学生手动点"下一页"
        return True
    return False
```

### 5.5 学生必须始终有显式控制权

**真实课堂里"老师等等，没跟上"是常态。** 做成按钮远比意图识别可靠，而且它是**演示/实用中最重要的兜底**：自动判定失灵的瞬间，能立刻手动推。

| 用户操作 | 语义 | 系统处理 |
|---|---|---|
| 点"下一页" | "我懂了，继续" | 跳过门二；标记 `user_advanced` |
| 点"上一页" / "这里没懂" | 重讲信号 | 回退到该页；进入重讲链 |
| 点"跳过本页" | 强烈跳过 | 本页未确认项 → `deferred`（**不丢，进待复习**） |

**关键原则**：学生手动跳过不等于"学会了"。未确认的 `must_teach` 知识点应转入 `deferred`（用户可选的"待回看"清单），**而不是静默丢弃**——这条把"跳过"从"丢信息"变成"改期"。

### 5.6 页尾探针与页边界

- 探针**只在页尾单元后**触发（`is_page_end`），不在每个单元后
- 页尾单元播完 → `PAUSING` → 窗口内无输入且超时 → 允许翻页
- 若学生在探针里提问 → 走 `YIELDING` → 答疑 → `RESUMING` → **回到该页页尾，重新判定一次**

### 5.7 翻页不是单行道

**学生必须能往回翻**，而且往回翻是一个**重讲信号**：

| 操作 | 语义 | 系统处理 |
|---|---|---|
| 点"上一页" | 我没懂 / 我想再看 | 回退该页；清空该页探针结果；**进入重讲链第 1 轮**（换说法重讲，选项见 §4.7） |

这条与 §4.7 连起来才完整：**往后是"跳过"，往回是"重讲"**。缺了往回这一半，学生发现没跟上时唯一的选择只剩下"继续听下去"——那课堂就退化成录音了。

**注意**：往回翻时 `covered` 台账**不删除**（I6：只增不改）。重讲只更新 `comprehension` 与 `q_rounds`，台账保留"曾经讲过"这一事实——否则后续"我们前面提过"的指代会失效。

## 6. 节奏与理解信号

### 6.1 三类信号

| 信号 | 来源 | 强度 |
|---|---|---|
| `confirmed` 确认 | 学生说"懂了""继续""嗯" | 强 |
| `vague` 模糊 | 探针超时无响应 / 简短情绪词 | **弱，不可作掌握度证据** |
| `confused` 困惑 | 学生说"没懂"、提问、点"不懂" | 强 |

### 6.2 核心原则

**学生的沉默 ≠ 理解。** 系统必须**主动探测**才能获得理解信号，不能把"没说话"当"听懂了"。

同时：**不能依赖学生配合。** 探针是"主动采集"，但学生不回应是常态，必须容忍并继续——**最坏情况是探针无效，不能是课堂卡住。**

### 6.3 探针的取舍

**探针不是免费的**：它打断连续性、增加摩擦、可能让学生觉得在被考。所以：

- **布点密度**：按页级或知识块，不是每个单元
- **单节课数量上限**：建议可配置，避免变成"节拍器"
- **优先探针的场合**：本页结论、前置知识依赖点、后续内容要用的关键点
- **绝不探针的场合**：纯叙述、举例、过渡段落

### 6.4 节奏的呼吸感

- 关键结论后留白（`pause` 标记），不要一路不停
- 一页讲完有停顿，不要立刻切页
- **防止疲劳**：连续讲解超过一定时长后，观察是否有任何输入；长时间无输入时，**建议**在一次主动探针里给"要不先休息一下"的选项（学生拒绝则继续）——**不要频繁弹出，更不要自作主张停止课堂**

## 7. 实现对应

### 7.1 后端编排

课堂是一张 LangGraph 状态图，`thread_id = (student, session)`，**一次课一个长线程**（不是一次请求一个线程）：

```
entry → segment_loop ─┬─(单元播完,队列空)→ segment_loop
                     └─(单元播完,队列非空)→ yield → triage ─┬→ redirect → answer
                                                           ├→ answer
                                                           └→ fixed_reply / empathy
                                                                  ↓
                                                              resume → segment_loop
```

- **位置、台账、队列必须进 State 并落盘**——课堂是长事务，必须能中断续跑
- **状态与讲解内容解耦**：状态机管"在干什么"，讲解单元管"讲什么"

### 7.2 前端需要的能力（个人自学场景的最简集）

| 区域 | 需求 | 优先级 |
|---|---|---|
| 课件区 | 当前页渲染；**元素级高亮**（锚点）；**分步显示**（reveal）；切页动画 | P0 |
| 语音 | 播放 + 暂停 + 可在句边界停止 | P0 |
| 字幕 | 与语音**逐字一致**，当前句高亮 | P0 |
| 输入区 | **快捷反馈条**（没懂/举例/慢点/继续）+ 一个"不懂"按钮 | P0 |
| 输入区 | 自由文本框（输入式提问） | P1 |
| 控制 | 上一页 / 下一页 / 重复本页 | P0 |
| 状态提示 | 让位期间显示"老师讲完这一段就回答你"，`PAUSING` 显示"在等你" | P0 |
| 课末 | "最没懂的一页"标记 / 待回看清单 | P1 |

**状态提示这一项容易被忽略但很关键**：段末让位会让学生等十几秒，**如果界面没有任何反馈，学生一定会以为系统卡了**。回执 + 进度提示是段末让位能成立的前提条件。

### 7.3 音频管线

| 项 | 设计 |
|---|---|
| **切分粒度** | 按讲解单元切分；单元内按**句**再切分（若干句一段），供 `pause` 与精确定位 |
| **预合成** | 课件讲解内容可在课前全量合成（个人自学场景**同一份内容跨学生复用**，性价比最高） |
| **句级缓存** | 按文本 hash 缓存音频 |
| **预置话术库** | 高频短话术**预合成**：回执、过渡、探针、重入、情绪安抚——**这是压低运行时延迟最划算的一招** |
| **运行时生成** | 仅用于：深度答疑的回答、重入话术、重讲的换说法/举例 |

**⚠️ 必须显式保留"运行时音频"通道。** 预合成覆盖不了答疑与重入，若架构上没留这条路，实现阶段会发现主流程走不通。

### 7.4 延迟预算

段末让位已经去掉了最糟的情况（学生不用等 LLM 生成完才开始听讲）。剩余两处延迟：

| 场景 | 路径 | 目标 | 实测 |
|---|---|---|---|
| **回执** | 本地触发预置话术 | **< 300ms 出声** | 1.3 秒（预置话术已预合成，等待来自"讲完当前单元"本身） |
| **快速反馈回应**（"没听懂"） | 预置短文/模板 + 缓存音频 | **< 1.5 秒出声** | 未单独计时 |
| **深度答疑** | 分流 + LLM 流式首句 + TTS 流式首句 | **首句音频 < 3 秒** | **5.7 秒**（含"讲完这一段"的剩余时长；纯生成段约 2 秒） |
| 翻页 / 下一单元 | 预合成音频 + 流式推送 | **≈ 0** | ≈ 0 |

**做法**：句级流式——LLM 出第一句就送 TTS，TTS 第一段音频就播，后面的边生成边接上。**不要让"整个回答生成完"再开始合成。**

实测补充（**这里踩过坑，务必照做**）：

- "过渡话术 → 分流 → 生成回答"这三步**必须并行**。串行实现时让位延迟是 20.3 秒；并行后 5.7 秒。
- 生成要**做成后台任务往缓冲里喂句**。先"整段生成完"再播的实现，学生在过渡话术后会静默空等
  （实测空等 15.9 秒），听起来像课堂卡死。
- 让学生一直等的从来不是 TTS，而是 LLM 的首句。TTS 首段音频在本地 1 秒内就绪。

### 7.5 上下文压缩（长课堂的硬约束）

一节 40 分钟课：8~15 页 × 数单元 + 提问与回答 ≈ 上万 token 且在增长。分层：

```
最近 2~3 页        → 完整讲解单元(细节)
更早内容           → LLM 压缩成"已讲内容摘要"
更早细节           → 不进上下文,按需从 covered 台账 + 讲解库检索
```

其中 `covered[]` 台账是**永不压缩的真相源**——摘要会失真，台账不会。

### 7.6 可观测性（调试与迭代的必需品）

课堂是长事务，出问题很难复现，必须记录：

- **状态转移日志**：每次 `phase` 变化的时间、触发、依据
- **让位与归位记录**：打断点、让位延迟、归位是否成功
- **探针日志**：发出、等待时长、响应、超时
- **翻页判定依据**：门一/门二/阻塞项各自的取值
- **锚点命中率**：低置信度锚点的出现频率（用于优化生成侧）

**其中"让位延迟"（学生提问到开始作答的间隔）是本设计最该盯的指标**——它是段末让位方案的核心代价。

### 8.3 实测暴露出来的、设计文档没写清的三件事

这三条是**做原型才发现的**，已回写进 `课堂状态机规范.md`：

1. **让位延迟的真实构成不是"单元剩余时长"**
   设计里写的"等于剩余单元时长"只在**音频流式合成**成立时才对。实测瓶颈全部在
   *首次生成*：过渡话术要等分流、要等回答的首句。所以 §7.4 的延迟预算必须写成
   "让位话术 + 分流 + 首句生成**并行**"，否则学生等的是三件事的和。

2. **"等这一段播完"必须带序号**
   播放协议原本只有 `speech_done`（没有 seq）。只要有一次错配（上一段的完成信号落在这一段上、
   或某段根本没回），状态机就会把"播完了"记到错误的段落上，然后**开始复读同一句话**。
   现在每段带自增 `seq`，前端原样回传，不匹配就不算播完。

3. **模型会在"不要重讲"的指令下复读刚讲过的话**
   小模型接到"别重复"反而会照抄上一句，也会把学生的问题抄回来当回答。
   这是**运行时必须用确定性代码挡掉的**一类失败（见 `TeachingFlow/classroom/llm.py` 的净化层与
   `machine.py` 的 `_collect_clean`），不能指望 prompt 自觉。

### 8.4 接入真实 PPT 之后，又补上来的四条

做"上传 PPT + 前端重绘"（§2.5 路线 3）时暴露的，已经写进 `TeachingFlow/classroom/README.md` §9：

1. **"讲到哪、指到哪"必须落在段落上，不能只落在形状上。**
   真实课件的"音标/释义/用法/搭配/例句"常常是**一个**文本框里的五个段落。
   只给形状级锚点，讲师就只能"指着整块"—— 说得出"我们看第三行"才是有效指认。
   于是锚点细到段落（`s04-sh02-p03`）、表格细到单元格（`s03-sh03-c04`）。

2. **模型规划的"定位文字"要当成不可信输入。**
   模型会写"我们来看第一题""后接物品名词"这类**它自己造的措辞**，正文里根本没有 ——
   这类操作会静默失效（永远不执行，或者全挤在第一句执行）。
   处理方式是三级降级 + 逐条留痕：原文子串 → 近似匹配 → 用目标元素自己的文字兜底 →
   退回本单元第 1 句；每一级的失败都在体检里报出来（`❌` 永不执行 / `⚠️` 定位可疑）。

3. **分步显示要留"学生不按剧本走"的出口。**
   分步显示（讲到才出现）对**自动**推进是对的，但学生自己按"下一页"的意图是
   "我要看这一页" —— 照藏不误的话，翻过去是一片空白，看着像课件坏了。
   手动翻页整页直接显示全。

4. **状态机里的异常必须喊出来，否则等于"老师突然不说话了"。**
   主循环里一个 `AttributeError`（实测就是翻页那行）就足以终结整节课，
   而 asyncio 会把异常吞掉、日志里可能一行都没有。
   现在主循环捕获后打印堆栈、给学生一句"这是程序问题，不是你的操作问题"，
   并留了 `CLASSROOM_TASKDUMP=1`：定期打印"每个协程停在哪儿"，用来定位死等。

### 8.5 验收本身也会骗人：两个"安静失效"

这一轮补的是**"操作真的生效了吗"**这件事，结果发现两处"什么都没发生"其实是坏的：

1. **一个被删掉的 DOM 节点，让整段验收逻辑静默跳过。**
   对比截图都用 `?bare=1`（把工具条、标题、说明都删掉，只留课件），
   而页面里更新页码的回调还在写那些节点的 `textContent` —— 抛在 `render()` 中间，
   后面的"应用操作"整段没执行。表现是"这套操作根本没效果"，
   真相是页面早在渲染那一步就停了。
   → 教训：**验收脚本必须把"明确的失败"和"什么都没发生"分开报**。
   这次是靠"和基准图比像素变化 0.00%"才暴露出来的；只看截图（页面是好的）永远看不出来。
2. **"发下去什么都不做"的操作会污染指标。** 计划里有 3 个 `reset_zoom`，
   而整份计划里一个 `zoom` 都没有 —— 它们什么都不会发生，却计入"课件操作 下发 N"。
   → 按页清理（`--fix-ops`），并给体检报告加上**操作类型分布**：
   没有分布，就永远看不出"这一课其实只用了一种操作"。

两条都指向同一句话：**凡是"没效果"和"没生效"长得一样的地方，都要单独设一个可观测量。**

## 9. 一句话总结

**这份设计的核心不是"让 AI 会讲课"，而是让一堂课有明确的状态、边界和归位路径。**

四个设计决定支撑它：

1. **让位式 + 段末让位** —— 把不可控的"打断"换成可控的"单元长度"
2. **讲解单元** —— 让位、音频、锚定、探针、翻页共用的最小单位
3. **状态机强制归位** —— `ANSWERING` 没有直通 `LECTURING` 的边，上课态从结构上守得住
4. **翻页双门判定** —— 从"讲完了"升级为"讲完了 + 听懂了"，把停顿、台账、重讲链串成一条线

**如果只能改一处**：把翻页从"讲完了就翻"改成"讲完了 + 确认听懂了"，并让"没听懂"触发**换讲法**而不是**重复讲**。
