# 预处理与课件库说明

> 适用范围：`TeachingFlow/classroom/` 当前实现（`preprocess.py` + `/preprocess` 页 + 单元总结）。
> 本文只回答三件事：课件从哪来、一次预处理到底跑了什么、走向图卡面上那句话是哪来的。

## 0. 一句话总览

```
上传 / 拷入 ──► TeachingFlow/classroom/pptx/<源>.pptx
                    │  后台作业（可轮询，可重跑）
                    ▼
      解析 ingest ──► 备课 plan ──► 预置路线 routes
                    │
                    ▼
  TeachingFlow/classroom/decks/<deck_id>/   deck.json · plan.json · plan.bak.json · media/ · source.txt
                    │
                    ▼
      /graph 主线卡面 = nodes[].summary（备课期顺手产出的那一句话，≤30 字）
```

## 1. 目录分工：源在 `pptx/`，产物在 `decks/`

| 位置 | 放什么 | 谁写 |
|---|---|---|
| `TeachingFlow/classroom/pptx/<文件名>.pptx` | 课件**源文件**（上传或手工拷入） | `preprocess.save_upload` |
| `TeachingFlow/classroom/decks/<deck_id>/deck.json` | 解析结果（可渲染、可锚定的课件结构） | `deck/pptx_ingest.py` |
| `TeachingFlow/classroom/decks/<deck_id>/plan.json` | 课堂脚本：讲解单元 + 锚点 + 课件操作 + 预置路线 | `run._save_plan` |
| `TeachingFlow/classroom/decks/<deck_id>/plan.bak.json` | **覆盖写之前**自动留的上一版计划 | `deck/store.backup_plan` |
| `TeachingFlow/classroom/decks/<deck_id>/source.txt` | 第一行记源路径，第二行记 sha1 | `deck/store.save_deck` |
| `TeachingFlow/classroom/decks/<deck_id>/media/` | 从 pptx 抽出来/下载下来的图片 | `deck/pptx_ingest.py` |

两条纪律，都是踩过坑之后定下来的：

1. **源与产物分开存**。`decks/<deck_id>/` 是要能进版本库、被人审的**产物**；pptx 原文件十几 MB、
   换一版就整份重来，混在一起会让"重新解析"看起来像在改产物，也让 `git status` 天天脏。
2. **`source.txt` 是"这份课件还能不能重新解析"的唯一答案**。它记的是当初解析的那个路径（绝对路径，
   或相对 `ROOT` 的路径），解析器**从不复制**原文件。仓库里那份 42 页真实课件就是靠它工作的：
   它的 pptx 在仓库根目录，`pptx/` 里从来没有过它 —— 少了这条回退，「重新解析+备课」在这份最要紧的
   课件上永远是灰的，用户为了重解析得先手动再传一遍 16MB。

## 2. 一次预处理到底跑了什么（作业模型）

`preprocess.py` 不实现解析/备课算法，它只回答一个问题：**谁在跑、跑到哪、成没成**。

### 2.1 四个 action

| action | 前置 | 做什么 | 写盘 |
|---|---|---|---|
| `full` | 源 pptx 存在 | 解析 → 备课 → 预置路线 | `deck.json` + `plan.json`（覆盖前备份） |
| `plan` | `deck.json` 存在 | 备课 → 预置路线（复用上次解析结果） | `plan.json` |
| `ingest` | 源 pptx 存在 | 只解析 | `deck.json` |
| `summarize` | `deck.json` + `plan.json` | 只补 `units[*].summary` | `plan.json` |

页面上「预处理（全链）」与「重新解析+备课」是同一个 `action=full` 的两副面孔：未解析过的行显示前者、
已解析的显示后者。同一条行并排两个一模一样的按钮，只会点错。

### 2.2 job 契约

`id · action · source · deck_id · stage · status · progress{done,total,label} · log_tail · backup · error · started_at · finished_at`

`stage` 只有六个值：`queued | ingest | plan | routes | done | failed`。补总结报的是 `plan`，
具体在做什么由 `label` 说（"补生成总结" / "补总结：第 N 页"）—— 加第七个值就是改契约，
前端与测试都得跟着动，而"补总结属于哪一段"本来就有答案：属于计划那一段。

### 2.3 三条纪律

1. **单飞**。同一份源（或派生同一个 `deck_id`）同时只允许一个 running 作业，再点返回带 `error` 的**同形** dict。
   不是优化：两个作业同时写同一个 `plan.json`，后写的会把先写的正常结果盖成半截。
   除了 `source` 也认 `deck_id`，因为 `"a b.pptx"` 与 `"a_b.pptx"` 会派生同一个 deck —— 它们抢的其实是同一份产物。
2. **备份在写盘之前**。`backup_plan` 永远先于 `_save_plan`；文件名固定 `plan.bak.json` 不带时间戳，
   因为这份备份是给"重备崩了"救场用的，攒多份之后"哪一份还能用"就变成了猜（要留历史是版本库的事）。
3. **失败不冒泡**。作业最外层兜住所有异常写进 `job["error"]`，绝不往外抛 —— 这是 `create_task` 起的后台任务，
   异常没人 await，只会被 asyncio 记一句 "Task exception was never retrieved"，而 job 永远停在 running，
   前端一直转圈。被拒的作业也留一条同形记录，前端只有一条渲染分支。

作业表活在**进程内存**里：服务重启即失，也不支持多 worker（见 §7）。

## 3. 端点与页面

| 端点 | 说明 |
|---|---|
| `GET /preprocess` | 操作台页面（`_page("preprocess.html")`，走 `?v=` 资源版本化） |
| `GET /api/preprocess/library` | `{ok, sources, decks, jobs}` —— `sources` 是 `pptx/` 一侧，`decks` 是 `decks/` 一侧的富信息行 |
| `POST /api/preprocess/upload` | `multipart/form-data`，字段名 `file`；失败一律 **400 + 人话**（不是 500） |
| `POST /api/preprocess/start` | `{name, action, slides?, force?}`；**被拒也是 200**，`ok=false` + `job.error` |
| `GET /api/preprocess/job/{id}` | 作业快照；查不到 404 且带 `error`（前端静默空 body 的表现是"进度条卡在 40%"） |
| `POST /api/deck/activate` | `{deck_id}` 切换「当前上课用哪份课件」；`""` = 手写演示课件。课堂在跑时 409 并拒绝写入 |

页面三个区块：上传 / 课件库（表格，每行四个动作按钮）/ 作业（阶段 + 进度条 + 日志尾）。

- **轮询只在 running 时进行**，用 `setTimeout` 续而不是 `setInterval` 常驻：这一页是操作台，允许轮询，
  但空闲时不许烧 CPU（启动台 `/hub` 那条纪律更严：一次都不许轮）。
- **样式写在页内**，不新建 `.css`：`web.py:_with_asset_versions` 是硬编码清单（tuple + replace 各一处），
  只加文件不登记的表现是"新页面配旧样式"，而且没有任何报错。

### 3.1 切换「当前上课用哪份课件」

课件从 `.env` 的 `DECK_ID` 来。页面（`/preprocess` 每行的「设为当前上课」+ 顶部常驻一行）与
`POST /api/deck/activate` 把它变成可点的一步：**下一节课立刻用新的**，并写回 `.env` 让重启后仍然保持。

| 情形 | 行为 |
|---|---|
| 切到已经在用的那份 | 幂等：`changed: false`，不写盘（课堂在跑也不拦，本来就没想换） |
| 目标 `deck_id` 没有 `deck.json` | 400，`.env` 与内存里的课件都不动 |
| 课堂正在跑 | **409**「先结课再换课件」，`.env` 与全局都不动 |
| 正常切换 | `load_course()` 成功**之后**才写 `.env`、才重绑 `settings/course/script`；任何一步失败都回滚 |

为什么"立刻生效"不需要重启：`ws_endpoint` 每开一节课才按**当时**的全局 `course` 装配 `Runner`，
已经在上的那一节自带 `course/script/state`。所以换课件既不必重启，也不会把正在上的课换掉 ——
而"课堂在跑时仍不许切"是产品判断：老师讲到一半课件换了，学生面前的表现是中途消失；
同时流向图/分支树会立刻显示另一份课件，与正在讲的那节不是同一件事。

> 一个必须知道的坑：`config.py` 只在 **import 时** `load_dotenv()` 一次，之后 `load_settings()` 读的是
> `os.environ`。所以切换时必须先写 `os.environ["DECK_ID"]` 再 `load_settings()`，只写 `.env` 的话
> 紧接着读到的还是进程启动时的旧值 —— 表现是"保存了但没生效"。

## 4. 单元总结（`unit.summary`）

### 4.1 什么时候产：和单元同一次调用

备课是**逐页一次**模型调用（`script_gen.plan_llm`），`summary` 就是同一次 JSON 输出里的一个字段 ——
不新增请求、不新增往返。规则兜底（`plan_rule`，不调模型）则取正文首句截断。

### 4.2 口径：≤30 字，首句优先

`state.clip_summary()`：把换行压成空格 → 取**首句** → 放不下才硬截到 29 字 + `…`。
为什么首句优先而不是一律等长切：讲解单元的第一句几乎就是"这一格在讲什么"，一律切会把句子砍成半句，
卡面上读到"好，我们来看 pack 的两个搭"比短一点的首句更难懂。上限是**字面的 30 字**，所以截断时补省略号后总长仍是 30。

### 4.3 三层落点，每一层的空值含义都不一样

| 层 | 空值意味着什么 | 谁兜底 |
|---|---|---|
| `script_gen.PlanUnit.summary` | **"这段还没补过"** —— 回填就是照它挑活的 | 不兜底，保持可空 |
| `state.LectureUnit.summary` | 运行期对读者不成立 | `__post_init__` 用 `clip_summary(text)` 兜 |
| `web` 的 `nodes[].summary` | 永远非空 | 没有第三层：上一行已保证 |

兜底放在 `LectureUnit` 而不是 `/graph` 的载荷里，是为了让所有构造点（备课链路 / 回填 / 测试夹具）一视同仁：
图只是读者，不必判空，也不必为两种来源各写一套。

> 注意：`_save_plan` 会把**空的** summary 像空 `variants` 一样不写盘。留着 `"summary": ""` 等于宣称
> "补过了，是空的"，下次回填会把它当成已完成，而重写旧计划还会让每个单元凭空多出一个空键。

### 4.4 显示：卡面是总结，全文仍看得到

`/graph` 主线卡面用 `nd.summary`；鼠标悬停的 `title` 与点开后的详情面板 `<pre class="gdtext">` 仍是全文。
老计划没有 `summary` 时前端才回落到 `clip(nd.text, 18)` —— 那时它只是"正文开头几个字"，
所以别把它当成"反正有兜底"：存量课件建议补一次。

### 4.5 回填：只补空的，正文一格都不动

`script_gen.backfill_summaries(deck, plan, llm, *, slides=None, on_progress=None)`：

- 只补空 summary（`force=True` 先清空再补，"补哪些"因此只有一个判据）；
- **逐页一次调用，且只对真有活要干的页调** —— 存量课件通常只差几页，为一页缺就整份重跑是白花额度；
- 模型挂了/输出认不出 → 回落正文截断，**回填永远不失败**；
- 只写 `units[*].summary`，所以对一份已经上过课的定稿计划也是安全的。

两条入口：`python run.py summarize <deck_id> [--slides 1-6] [--force] [--dry-run]`，或页面上的「补生成总结」
（后者走 `action=summarize` 作业，因此天然带了单飞、日志、备份）。`--dry-run` 只统计待补数量，不调模型、不写盘。

## 5. 三个会静默出事的坑

这三个的共同点：**没有任何报错**，页面照常打开，只是东西没了或显示错了。

### 5.1 `_save_plan(path, plan, routes=None)` 会把 `routes` 键整个吞掉

`_save_plan` 的 data 来自 `plan.to_json()`，而 `LessonPlan` 根本没有 `routes` 字段。实测：

```
透传 routes  -> routes 键在: True  | 条数: 1
routes=None  -> routes 键在: False | 条数: 0      ← 静默消失，无异常无警告
```

所以凡是"把已有计划重写一遍"的路径（补总结、`--fix-ops`），都必须从**原始文件**把 `routes` 取回来再透传。
走错这一步，走向图上那十几条预置支线会凭空消失。

### 5.2 `has_summary` 曾经和 `unit.summary` 同名不同义

`preprocess._entry` 最初的 `has_summary` 读的是 `plan.json` 的 `session_goals`（整节课**总览**），
而单元总结是 `units[*].summary`（**每格**）。同名字段会让页面把"整节课有总览"显示成"总结已补全"。
现在叫 `has_goals`，单元级的叫 `summarized`（已总结的单元数 + `units` 总数）。

### 5.3 `library()` 只看 `pptx/`，页面却不能只看它

源不在 `pptx/` 的课件（例如仓库里那份真实课件）在 `library()` 里没有行 —— 只读它，页面会在 `decks/` 明明
有一份能上课的课件时显示"空课件库"，而"补总结"恰恰只有那一侧能点。所以 `preprocess.deck_rows()` 以
`deck_store.list_decks()` 为基座，再补上单元数/已总结数/有没有备份/源文件还找不找得到。

## 6. 怎么观测与体检

| 想看什么 | 看哪里 |
|---|---|
| 现在有哪些源、哪些课件、缺多少总结 | `GET /api/preprocess/library` |
| 某个作业跑到哪了 | `GET /api/preprocess/job/{id}`（`stage` / `progress` / `log_tail`） |
| 存量课件差多少总结（不调模型、不写盘） | `python run.py summarize <deck_id> --dry-run` |
| 卡面那句话对不对 | `/graph` 点开卡片看详情面板（summary 与全文并列） |
| 契约有没有被改坏 | `tests/test_script_graph.py`（`NODE_KEYS` 精确断言 nodes 键集合）、`tests/test_preprocess*.py` |

## 7. 已知边界（当前不做的事）

1. **作业表在进程内存**：重启即失，没有持久化；多 worker/多进程会各有一份表，单飞只在进程内成立。
2. **上传上限 200 MB、只认 `.pptx`**：别的格式解析器读不了，列出来也点不动，所以当场就拒（400 + 人话）。
3. **补总结仍逐页串行调用**：42 页约 42 次，与备课是同一条纪律（不并发打同一个服务商）。
4. **`source.txt` 回退需要源路径仍然有效**：源文件被移走/改名后回退失效，需重新上传。
5. **不做课件版本管理**：同一 `deck_id` 覆盖，只留一份 `plan.bak.json`。要保留每一版请用版本库。
