# 课程生成与渐进式课件

> 这一页讲的是**"登录之后第一眼看到的那个界面"**：和模型聊清楚想学什么 → 确认 → 排大纲 →
> 改大纲 → 逐章设计每一课 → 存进「我的课堂」→ **上到哪一课才生成哪一课的 PPT**。
>
> 代码在 `course_plan.py`（纯函数：规整 / 蓝图 / 渲染）+ `course_builder.py`（会话状态机 +
> 模型工具调用 + 后台任务 + 落盘 + 入库）+ `app/routes/builder.py`（HTTP 面）。

---

## 1. 为什么不是"一句话直接出片"

`TeachingFlow/flow.py` 的 S0 是「一句话 → 关键词抽学段/学科 → 内置模块表 → 估周期」。
它很快，但**它没有问过用户**：想学到什么程度、现在有什么基础、能投入多久 —— 这三个问题
决定了课件的深度、例题难度与单元密度。不问就排，代价是整份课都偏。

所以这条路补的正是那一步，其余一概复用既有能力：

| 环节 | 谁干的 |
|---|---|
| 问清楚需求 | 模型 + 两个工具（`ask_user_question` / `confirm_course_requirements`） |
| 排章 / 单元 | 模型一次调用 → `course_plan.normalize_outline` 规整 |
| 单元课程安排设计 | 模型逐章调用 → 规整成 `unit_design_<uid>.json` |
| 排课产物 | `outline.json` / `01_blueprint.yaml` / `02_targets.json` / `03_unit_*.result.md`（与 flow.py 一次运行同形） |
| 出片 | `python flow.py … --resume <run> --unit <uid>`（S4 页骨架 + S5 渲染），沿用既有产片链路 |

## 2. 状态机（服务端 `phase`）

```
        ┌────────────┐  回答够了   ┌──────────────────────┐
        │ clarifying │───────────▶│ confirming_requirements│
        └────────────┘            └──────────────────────┘
              ▲                              │ 符合
              │ 不符合（feedback）            ▼
              └──────────────────  ┌──────────────────┐
                                   │ generating_outline│（后台任务）
                                   └──────────────────┘
                                             │
                                             ▼
                                   ┌──────────────────┐
                                   │  editing_outline │ ← 用户改标题 / 增删单元 / 调顺序
                                   └──────────────────┘
                                             │ 手动确认
                                             ▼
                                   ┌──────────────────┐
                                   │ generating_course │（逐章生成单元设计 → 入库）
                                   └──────────────────┘
                                             │
                                             ▼
                                   ┌──────────────────┐
                                   │      ready       │ → 去「我的课堂」按课生成 PPT
                                   └──────────────────┘
```

`generating_*` 期间后端对新的对话/编辑一律回 409（同一时间只允许一个后台动作），
页面靠 `GET /course-builder/sessions/{id}` 轮询（1.2s）把进度画出来。

## 3. HTTP

| 方法 | 路径 | 干什么 |
|---|---|---|
| POST | `/api/v1/course-builder/sessions` | 第一句话进来 → 建会话并立刻跑一轮模型（返回的已经是"模型在提问"） |
| GET | `/api/v1/course-builder/sessions?limit=` | 最近的会话（`active` = 正在生成的那条） |
| GET | `/api/v1/course-builder/sessions/{id}` | 完整快照：消息 / 需求 / 大纲 / 任务账本 / `llm` 提示 |
| POST | `…/{id}/messages` | 用户说一句话 → 标记上一次提问已答 → 跑一轮 → 回快照 |
| POST | `…/{id}/confirm-requirements` | `{accepted:true}` 开始排大纲；`false` + `feedback` 回到提问 |
| POST | `…/{id}/outline` | 保存用户编辑过的大纲（结构不可用直接 400 并说清哪一条） |
| POST | `…/{id}/outline/confirm` | 确认大纲（可带最终版）→ 生成单元设计 → 入库 |
| DELETE | `…/{id}` | 删会话（不动已经入库的课程） |
| GET | `/api/v1/courses/{id}/ppt-plan` | 每课的 PPT 状态 + `next_unit_id` |
| POST | `/api/v1/courses/{id}/ppt/next` | 顺序生成下一个还没有 PPT 的单元 |
| GET/POST | `/api/v1/units/{id}/ppt` | 这一课的 PPT 任务状态 / 单独生成 |
| POST | `/api/v1/units/{id}/ppt/cancel` | 取消（杀整棵进程树） |

**为什么都挂在 `/course-builder` 下**：它是一条流程（对话 → 确认 → 大纲 → 设计 → 入库），
不是五个独立资源。PPT 的三个口是例外 —— 用户是从**课程页**点进来的，路径必须落在
`/courses/{id}/ppt-plan` 与 `/units/{id}/ppt` 上。

## 4. 两个工具（模型的"手"）

模型必须**每一次回复都调用其中一个**（提示词里是硬要求）：

```jsonc
// 1) 问细节：一次最多 3 个问题，每题给可点选的选项
{"name": "ask_user_question",
 "arguments": {"intro": "…", "questions": [
   {"id": "depth", "header": "想学到什么程度", "question": "…",
    "options": [{"label": "掌握并能做题", "description": "概念清楚，常见题会做"}], "multiple": false}]}}

// 2) 请用户确认整理结果
{"name": "confirm_course_requirements",
 "arguments": {"reply": "…", "requirements": {
   "course_title": "…", "subject": "…", "stage": "大学", "goal": "…",
   "student_level": "基础", "prerequisite": "…", "weeks": 8,
   "hours_per_week": 3, "key_topics": ["…"], "summary": "…"}}}
```

服务商不支持 function calling 时，`course_builder._ask_model` 会退一步：用一段
「只输出 JSON」的约定再问一次（`_worth_json_retry` 只对"看起来不认 tools"的 4xx 重试；
502 / 连不上 / 超时是上游坏了，再问一遍只会让用户多等一整个超时）。

## 5. 落盘形状（与一次 flow.py 运行同形）

```
TeachingFlow/runs/<日期>/<课程名>_<时分秒>/
├─ outline.json             结构化大纲（章 → 单元 + 知识点）：课程详情页与 PPT 都读它
├─ outline.md               同一份大纲的人类可读版（审计用）
├─ 00_spec.json             flow.py --resume 读回的 FlowSpec
├─ 01_blueprint.yaml        S3/S4/S5 认的蓝图（units[].lesson_status 一律 pending）
├─ 02_targets.json          全部单元（flow 的 S2 也会按 --unit 重新挑）
├─ 03_unit_<uid>.result.md  10 模块的单元教学文本（由设计确定性渲染，见 §6）
├─ unit_design_<uid>.json   **单元课程安排设计**（知识点 / 教学流程 / 例题 / 练习 / 页骨架）
└─ manifest.json            课程标题、科目、produced…
```

课程 id / 单元 id 用的是 `studio/catalog.py` 的**同一套哈希口径**
（`sha1(相对 runs 父目录路径)[:12]`；单元是 `sha1(课程id/章名/第M单元-标题.pptx)`）。
口径一致才敢让用户点「重新扫描」：不然同一门课会被再插一遍，学生的进度跟着丢。

## 6. 单元设计为什么要渲染成 10 个模块

`PromptTemplate/unit_bridge.py` 只把 `teacher_unit` 的 **5 个教学内容模块 + 【课件大纲】** 喂给
`teacher_ppt`，其余 5 个（定位 / 难度 / 作业 / 解锁…）是教学管理信息，上 PPT 会把模型带跑。

所以 `03_unit_<uid>.result.md` 必须是这 10 个模块、这 10 个名字：

```
1. 【本单元定位】 2. 【难度调整说明】 3. 【本课目标】 4. 【知识讲解】 5. 【典型例题】
6. 【易错提醒】   7. 【小结】         8. 【课件大纲】 9. 【单元作业】 10. 【完成后解锁】
```

渲染是**确定性**的（`course_plan.render_unit_markdown`）：同一份设计永远得到同一份 md。
否则"同一节课两次出片内容不一样"这件事会没法解释。

## 7. 渐进式出片（一课一课来）

`POST /courses/{id}/ppt/next` → 后台任务：

1. `_plan_unit()`：从 `outline.json` 按 `order_index` 找回这一课在大纲里的位置（蓝图 id `ch01-u1`）。
   库里那个单元 id 是 sha1，flow 的 `--unit` 只认蓝图 id，**两者之间唯一的桥是顺序**。
2. `python flow.py "<课程名>" --resume <run> --unit ch01-u1 --units 1 --to render --no-classroom --no-input`
   —— S3 会复用已经写好的 `03_unit_*.result.md`（`flow.py` 为此加了一条复用分支），
   S4 出页骨架、S5 产片。
3. 失败或零产物时**兜底合成**：`_synthesize_pptx` 直接按 `unit_design_<uid>.json` 用
   python-pptx 拼一份课件。产品上必须兜 —— 学生点了"生成下一课"就该拿到课件，
   而不是一条红色错误；这也让没有 key 的机器能走完整条流程。
4. 成功后把 `pptx_path` / `slides` 写回单元，再跑一次 `deps.prepare_unit()`（解析 + 备课），
   于是这一课立刻可以进课堂。

**一次只做一课**（全局单并发）：第二次点会得到 409，并说明"哪一课正在生成"。
取消 = 杀整棵进程树（flow 自己会拉起 pipeline / LibreOffice）。

## 8. 没有模型时会发生什么

三层各自降级、都不报错：

| 哪一层 | 降级 |
|---|---|
| 对话 | `_offline_turn`：按「程度 → 基础 → 周期」的固定顺序问两个问题，然后请用户确认 |
| 大纲 / 单元设计 | `course_plan.offline_*`：按需求里的重点排 2~4 章，知识点取自大纲 |
| 出片 | flow.py 失败 → `_synthesize_pptx` 合成一份能上的课件 |

页面会**说出来**：对话流里插一条 `kind="notice"` 的说明，`llm.ready=false` 时页脚还有一行提示。

## 9. 对账与自愈

`course_builder.reconcile()` 在服务启动时跑（`app/__init__.py` 的 lifespan）：

* 停在 `generating_*` 的会话 → 回到 `editing_outline`（有大纲）或 `confirming_requirements`，
  `task_status=interrupted`；
* 停在 `queued/running` 的 PPT 任务 → `interrupted`。

不做这件事的代价很具体：页面永远显示一个不动的进度条，而且"一次只做一课"的名额被占着，
用户从此点不动「生成下一课」。
