## 0. 一页速览

### 0.1 一句话

**课前由 Agent-P 把课件编译成「带变体的脚本」；上课时 Agent-J 在单元边界做亚秒级选择，Agent-C 在几分钟之外提前生产候选，两者通过一个限 5 个、带版本的候选池解耦。**

### 0.2 拓扑

```text
┌──────────────── 课前 ────────────────┐
│  Agent-P（备课 profile）              │
│    PPT + 学员画像                     │
│      → LessonScript + 变体库(v0/v1/v2) │
│      → plan.json（落盘，运行期只读）   │
└───────────────────┬───────────────────┘
                    │
┌───────────────────▼─────────────────── 上课中 ───────────────────┐
│                                                                  │
│  状态机主线（8 相位，永不停摆）                                    │
│      │ 单元边界                                                   │
│      ├──→ 决策点 ──→ Agent-J（不是 agent：算法或单次 LLM）          │
│      │                  输入：事实块 ≤100 字 + 候选 ≤5×30 字        │
│      │                  输出：一个 candidate_id 或 none             │
│      │                  超时 → 默认 v0                             │
│      │                                                            │
│      └──→ 候选池（上限 5，带版本）←── Agent-C（每 60s 醒一次）      │
│                  ↑ 写入                   读：全脚本 + 快照         │
│            预置变体（P 落盘）             约束：只对 [+5,+15] 上货   │
│                                          只读 get_state，不消费事件 │
└──────────────────────────────────────────────────────────────────┘
```

### 0.3 五个关键数字

| 参数 | 取值 | 依据 |
|---|---|---|
| J 的输入上界 | 事实块 ≤100 字 + 候选 ≤5×30 字 | prefill 是延迟唯一主因（§9.2 of 前身文档） |
| J 的宽限等待 | 300 ms | 一格前瞻已覆盖大部分，边界上只补一点点 |
| C 的唤醒周期 | 60 秒 | 保证同一节点被观察 3~5 次（多次逼近） |
| C 的上货窗口 | `[当前+5, 当前+15]` 单元 | 3~4 分钟；`+5` 是容错窗口 |
| 候选池上限 | 5 个 | 池子大了 J 就慢，两个 agent 互相拖累 |

### 0.4 三条铁律

1. **脚本运行期只读。** P 写盘，J/C 都不写脚本。
2. **J 永远不能阻塞课堂。** 有宽限、有超时、有默认值。
3. **权限靠工具面隔离，不靠提示词。** C 的工具白名单里没有 `write_plan`。

### 0.5 已定决策（2026-10-24）

| # | 决策 | 取值 | 备注 |
|---|---|---|---|
| **D1** | J 用什么模型 | `opencode_go` / **`deepseek-v4.1-flash`** | **优先 flash**：它是快变体，直接服务 J 的延迟要求。**升级路径**：若实测判断质量不够（选错/不选），改一个字段升到 `deepseek-v4.1` |
| **D2** | provider 隔离 | **provider 代码共用，实例隔离** | 一套 provider 配置；J 用独立的 `AsyncOpenAI` 实例（独立连接池）。服务商侧看到的就是同账号的多个并发调用 |
| **D3** | 实施顺序 | **阶段 1 先做** | 不要求变体质量，重点是**真实上课中的表现**。验收标准见 §12 |

> **D3 的"不要求质量"是什么意思**：变体内容可以粗糙、可以是规则模板、可以是原话复述——**只要不是空的**。重点是让它真的在课堂上被切换、被播出、被记录，从而拿到"这套机制在真实课堂里是什么手感"的一手数据。质量留给阶段 1.5 再迭代。

## 3. 角色分工

| 角色 | 时机 | 形态 | 延迟预算 | 失败后果 |
|---|---|---|---|---|
| **P** 备课 | 课前，一次性 | 通用 agent + profile | 分钟~小时 | 没课可上，必须重跑 |
| **J** 选择器 | 上课中，单元边界 | **不是 agent**：算法或单次 LLM 调用 | < 300 ms 宽限 | 用默认 v0，无感 |
| **C** 造分支 | 上课中，每 60s | 通用 agent + profile，常驻 | 3~4 分钟 | 少几个候选，无感 |

### 3.1 为什么 J 不是 agent

agent 的形态 = **循环 + 工具 + 历史**。J 三样都不需要：

- 不需要循环（单轮）
- 不需要工具（输入已由状态机组装好）
- 不需要历史（每次只给当前事实）

把它做成 agent，等于给它装上它必须甩掉的三样负担，直接摧毁延迟上界。

### 3.2 provider 与模型绑定（已定 · D1 + D2）

| 角色 | provider | model | 客户端实例 |
|---|---|---|---|
| 课堂状态机（现状） | `opencode_go` | `deepseek-v4.1-flash` | `LLM` 内一个 `AsyncOpenAI` |
| **J** | `opencode_go` | **`deepseek-v4.1-flash`** | **独立 `AsyncOpenAI`** |
| **C** | 待定（建议 `ollama`） | — | 独立 |

**隔离口径（D2 原文）**：**provider 代码共用，实例隔离。** 从服务商侧看，就是同一个账号的多个并发调用。

**拆开说，只有一件事在隔离**：

| 层面 | 隔离吗 | 为什么 |
|---|---|---|
| provider 配置（base_url / key / model / headers） | ❌ **共用** | 一套配置，一份代码 |
| **`AsyncOpenAI` 客户端实例** | ✅ **隔离** | 各自独立的 httpx 连接池——J 不会排在课堂的长流式生成后面**抢连接** |
| `x-opencode-session` | ❌ **共用** | 不人为制造不同会话头；服务商侧只当并发调用处理 |
| model id | ❌ **共用**（都是 flash） | 见下 |

**为什么共用 model id 不是问题**：J 的提示词是「固定短系统提示 + 每次不同的事实块」，课堂的提示词是「长教学人设 + 课件上下文」。两者**前缀完全不同**，prompt cache 天然不命中，不存在互相污染。

**真正的隔离点是连接池**。这一点值得单独强调：课堂的 `answer_stream` 会持有一个流式连接 10~30 秒，如果 J 复用同一个客户端，它就可能在这条长连接上排队等空闲连接。**独立实例 = 独立连接池 = 零排队。**

**实现方式**（只换实例，不动配置）：

```python
# provider 配置原样复用，只新建一个客户端
J_LLM = LLM(settings)          # LLM.__init__ 内部会新建 AsyncOpenAI
# 或更省：直接复用同一个 Settings，LLM 已经是独立实例
```

`LLM.__init__` 每次都会 `AsyncOpenAI(...)`（`llm.py:398`），所以**多 new 一个 `LLM` 就是实例隔离**，不需要改 `config.py` 任何一行。

**仍存在的风险**：provider 侧限流（同账号并发上限）。这是 §13 #2 的观测项——若实测发现 J 与课堂互相拖慢，J 才换到完全独立的 provider。

## 4. 数据结构

> 本节是全篇的实现核心。所有字段名即代码字段名。

### 4.1 `UnitVariant` —— 一个单元的另一种讲法

```python
@dataclass
class UnitVariant:
    """一个讲解单元的替代表述。v0 是主 text，其余都在这里。"""
    variant_id: str                 # "v1" | "v2" | "c1" ...
    label: str                      # 给人看："换说法" / "举例子" / "更浅"
    text: str                       # 这个变体的完整讲解文本
    anchors: list[dict] = field(default_factory=list)   # 空 = 沿用主单元
    ops: list[dict] = field(default_factory=list)       # 空 = 沿用主单元
    est_sec: float = 0.0            # 派生：len(text)/5.0
```

**为什么 v0 不进 `variants`**：保持向后兼容——现有 `PlanUnit.text` 就是 v0，老 `plan.json` 不加字段也能跑。

### 4.2 `PlanUnit` 扩展（`script_gen.py:55`）

```python
@dataclass
class PlanUnit:

    text: str                                        # v0（主讲法，不变）
    anchors: list[dict] = field(default_factory=list)
    ops: list[dict] = field(default_factory=list)
    kp: list[str] = field(default_factory=list)
    must_teach: bool = True
    is_page_end: bool = False

    variants: list[dict] = field(default_factory=list)   # UnitVariant 的 dict 形式
```

`LessonPlan.from_dict` 已经用 `PlanUnit(**u)` 构造，新增带默认值的字段不会破坏旧文件。

### 4.3 `LectureUnit` 扩展（`state.py`）

```python
@dataclass
class LectureUnit:
    ...

```

**类型写成 `list` 而非 `list[UnitVariant]`**，理由同现有 `ops` 字段的注释：让 `state` 不依赖上层模块，可脱网单测。

### 4.4 `Candidate` —— 候选池里的一项

```python
@dataclass
class Candidate:
    candidate_id: str          # 幂等键，如 "c-S03U02-001"
    target_unit: str           # 目标 unit_id；空串 = 任意单元（纯条件触发）
    variant: UnitVariant       # 选中后要用的讲法
    when: dict                 # 结构化触发条件（见 §4.6）
    source: str                # "preset" | "agent_c"
    created_at: float          # monotonic
    created_at_unit: str       # 造它时课堂在哪个单元
    expires_at_seq: int        # 单元序号超过它即作废
    status: str = "alive"      # alive | consumed | expired
    version: int = 1           # 同 id 重写时自增
```

### 4.5 `CandidatePool` —— 单一真相

```python
class CandidatePool:
    CAP = 5

    def put(self, cand: Candidate) -> bool:      # 幂等：同 id 覆盖并 version+1
    def candidates_for(self, unit_id: str, facts: "DecisionFacts") -> list[Candidate]:
        """返回该单元可用且条件匹配的候选，按 source 优先(agent_c > preset)、再按新近排序。"""
    def mark_consumed(self, candidate_id: str) -> None
    def expire_stale(self, current_seq: int) -> int
    def status(self) -> dict:                    # {"alive":n,"consumed":n,"expired":n}
```

**只有 J 读、只有 C 写**（P 的预置变体在开课时批量灌入）。

### 4.6 触发条件：结构化，不用自然语言

```json
{"consecutive_confused": {">=": 2}, "probe_result": {"in": ["timeout"]}}
```

**扁平结构 + 隐式 AND**，只支持三种 key（先跑稳再扩）：

| key | 类型 | 含义 | 取值来源 |
|---|---|---|---|
| `consecutive_confused` | int | 当前单元连续"没懂"次数 | `state.q_rounds` + pending |
| `probe_result` | str | 最近一次探针结果 | `state.probe_log[-1].result` |
| `comprehension` | str | 当前单元理解信号 | `state.comprehension` |

**为什么必须是结构化的**：如果条件是自然语言（"当学生困惑时"），J 就得*理解*它——那 J 就不能只输出枚举了，延迟上界立刻失守。结构化条件让匹配退化成一次字典比较，甚至状态机自己就能做。

### 4.7 `DecisionFacts` —— J 看到的全部事实

```python
@dataclass
class DecisionFacts:
    unit_id: str
    slide: int
    consecutive_confused: int = 0
    probe_result: str = ""          # "" | confirmed | interrupted | timeout
    comprehension: str = ""         # "" | confirmed | vague | confused
    q_rounds: int = 0

    def to_prompt_block(self) -> str:
        """渲染成 ≤100 字的事实块（J 的输入上界之一）。"""
```

## 6. Agent-J（选择器）实现

### 6.1 接口

```python
class DecisionProvider(Protocol):
    async def decide(self, facts: DecisionFacts,
                     candidates: list[Candidate]) -> str | None:
        """返回 candidate_id；None = 用默认 v0。"""
```

两个实现：

| 实现 | 用途 | 延迟 |
|---|---|---|
| `RuleDecider` | 纯规则：条件匹配 + 优先级 | ~0 |
| `LlmDecider` | 单次 LLM 调用（**已定：`opencode_go` / `deepseek-v4.1-flash`**，见 §3.2） | 0.3~1.5 s |
| `ExternalMcpDecider` | 转发外部端点（实验用） | 不可控 |

**默认 `RuleDecider`，没有匹配时才升到 `LlmDecider`。** 大部分决策根本不需要模型。

> **阶段 1 只用 `RuleDecider`**（见 §12）：先验证"变体切换"这条链路通不通，J 的 LLM 版留到阶段 2。

### 6.2 输入上界（硬约束）

```text
事实块：≤100 字
候选：≤5 个 × ≤30 字摘要
系统提示：固定（可命中 prompt cache）
历史：0
输出：{"choice": "c1"} 或 {"choice": "none"}
```

约 250~300 token。**任何一项放宽，延迟上界就失守。**

### 6.3 提示词骨架

```text
你是课堂的节奏选择器。只能从给定候选里选一个，或选 none。

当前单元：S03-U02（第 3 页）
事实：连续没懂 2 次 / 探针 timeout / 理解信号 confused / 已重讲 1 轮

候选（只能选一个）：
  c1  更浅的讲法：用天平打比方
  c2  举一个具体数字例子
  c3  跳过本单元，记入待回看

只输出 JSON：{"choice":"c1"}
```

### 6.4 零阻塞的三段式

这是 J 能"不拖慢课堂"的关键：

```text
① 单元 N 开始播放时 ──→ 立即发出 decide()（不 await）
② 单元 N 播放期间     ──→ 结果在后台返回
③ 单元 N 播完（边界） ──→ 消费结果：
                           · 已返回     → 直接用
                           · 未返回     → 最多再等 300 ms
                           · 仍未返回   → 用默认 v0
```

**为什么不是"边界上现问"**：那样每次都要等满一次 LLM 往返。一格前瞻把等待藏进播放时间里。

**为什么还要 300 ms 宽限**：学生在单元 N 期间提问会让状态变化，一格前的决策可能已过期。宽限窗口让"最后时刻的修正"有机会赶上来。

### 6.5 版本校验（必须）

决策请求携带 `(unit_id, state.seq)`。消费时校验：

```python
if decision.unit_id != current_unit or decision.seq != state.seq:
    discard()   # 位置变了（学生插话导致让位/归位），决策作废
```

**不校验就会出错**：单元 N 期间学生提问 → 让位 → 归位后可能回到 N 或跳到 N+1，此时用一格前算的决策就是错位的。

## 7. Agent-C（造分支）实现

### 7.1 生命周期

```text
课堂开课（Runner 创建 Machine）
   ↓
生产期：每 60s 醒一次
   ↓
停止期：剩余单元 < 5 或池子满且无腾位
   ↓
课堂结束（machine._finished）→ C 退出
```

### 7.2 每次唤醒的完整流程

```python
async def tick():
    # ① 读快照（零副作用）
    snap = await mcp.get_state()

    # ② 规则门卫（纯 Python，≈0 成本）
    if not gate_open(snap, pool):
        return                      # 不调 LLM

    # ③ 组装自包含输入（无历史）
    window = script.units[seq + 5 : seq + 15]
    prompt = build_prompt(snap, window, pool.status())

    # ④ 单次 LLM 调用
    proposals = await llm_json(prompt, schema=ProposalList)

    # ⑤ 校验（与 P 同一把尺子）
    for p in proposals:
        if not validate_variant(p.variant, deck, window_unit):
            continue

    # ⑥ 幂等写池
    for p in proposals:
        pool.put(Candidate(...))
```

### 7.3 规则门卫（决定"这次要不要调 LLM"）

```python
def gate_open(snap, pool) -> bool:
    if pool.status()["alive"] >= CandidatePool.CAP:  return False
    if snap.remaining_units < 5:                     return False
    return any([
        snap.new_confused_since(last),      # comprehension 新增 confused
        snap.deferred_grew,                 # 待回看变长
        snap.consecutive_probe_timeout >= 2,# 连续探针超时
        snap.repeated_question,             # 最近问答出现重复追问
        pool.just_consumed(),               # 腾出位置
    ])
```

**40 分钟 = 40 次唤醒，但只有 8~15 次真的调模型。**

### 7.4 上货窗口

```python
EARLIEST_OFFSET = 5     # 当前 +5
LATEST_OFFSET   = 15    # 当前 +15

def target_window(current_seq: int, total: int) -> range:
    lo = min(current_seq + EARLIEST_OFFSET, total)
    hi = min(current_seq + LATEST_OFFSET + 1, total)
    return range(lo, hi)
```

**用单元序号，不用时间戳**：时间戳会漂移（学生插话、TTS 抖动、探针窗口可变）。

**`+5` 的意义 = 容错窗口**：C 连续失败 5 个单元（80~180 秒）内，J 仍有预置变体可用。

### 7.5 无私有记忆

| 记忆类型 | 有吗 |
|---|---|
| 会话历史 | ❌ |
| 自己的决策记录 | ❌ |
| **候选池（共享）** | ✅ |
| **学员画像（只读）** | ✅ |

**stateless worker + shared store**。收益：可重启、可复现、可审计。

每次 LLM 调用的输入自包含：`当前快照 + 窗口内脚本 + 池子现状 + 固定系统提示`（约 3000 token）。

### 7.6 工具白名单

```python
ALLOWED = [
    "get_state",        # 读快照（零副作用，可反复读）
    "read_script",      # 读全脚本（含未来单元）
    "read_memory",      # 读学员画像
    "write_candidate",  # 只写候选池
]
```

**没有 `write_plan`。** 这是机制层面的隔离。

### 7.7 为什么不消费 `get_events`

`EventBus` 是**消费即消失**的（`mcp_server.py` `EventBus.get_events`）。两个消费者会互相偷事件——J 拿到的那条，C 就永远看不到。

C 只读 `get_state`（幂等、无副作用）。

## 8. 条件匹配

### 8.1 匹配算法

```python
_OPS = {">=": operator.ge, "<=": operator.le, "==": operator.eq,
        "in": lambda a, b: a in b, "not_in": lambda a, b: a not in b}

def matches(when: dict, facts: DecisionFacts) -> bool:
    """扁平条件 + 隐式 AND。任一 key 不满足即 False。"""
    for key, cond in (when or {}).items():
        actual = getattr(facts, key, None)
        for op, want in cond.items():
            fn = _OPS.get(op)
            if fn is None or not fn(actual, want):
                return False
    return True
```

### 8.2 J 的候选筛选

```python
def candidates_for(self, unit_id, facts) -> list[Candidate]:
    alive = [c for c in self._items.values()
             if c.status == "alive"
             and (not c.target_unit or c.target_unit == unit_id)
             and matches(c.when, facts)]
    # agent_c 造的优先（更贴合当下学生），同源按新近
    alive.sort(key=lambda c: (c.source != "agent_c", -c.created_at))
    return alive[:5]          # ← 硬上限，喂给 J
```

### 8.3 默认路径

```
候选为空            → 用 v0（主讲法）
全部条件不匹配      → 用 v0
J 超时              → 用 v0
J 返回 none         → 用 v0
```

**四种失败都收敛到同一个默认值**，课堂行为可预测。

### 阶段 1：Agent-P（备课工作台）· **已定：先做（D3）**

### C.3 实现中对本设计的修正（照原文实现会出错的地方）

1. **§6.5 的位置键不能用 `state.seq`。** 状态机每吐一句都 `_log_utterance → state.emit → seq += 1`，照原文实现会让每个单元 100% 判 stale、J 永远回 v0。改为由调用方提供 `(slide_index, seg_index, 让位纪元)`，`Director` 只做比对、不猜位置。
2. **§9.1 的决策点必须在 `if st.pending_questions` 之后**（原文如此，代码已按其注释顺序落地）。放在之前会让「提问恰好落在单元末尾」的学生干等一整段变体重播才被回应。
3. **§4.5「开课时批量灌入预置变体」在 CAP=5 下不可行**（一节 40 分钟课有上百个单元）。改为单元开始时装载当前单元的预置变体，`+5` 容错窗口因此天然成立。
4. **§7.2 的窗口伪代码 `units[seq+5:seq+15]` 少算 +15 那一格**，按 §7.4 的 `hi = current+15+1` 实现（11 格）。
5. **`q_rounds` / `comprehension` 的键不一致**：`state.py` 注释写 kp，`machine.py` 实际写 unit_id。`facts_from_state` 双键兼容、取最坏值。
6. **`probe_log[-1].result` 常为空串**（探针先 append 后 close），改为取最后一条有结论的探针。

### C.4 真实触发链路的补正（初版验收的漏判，必读）

C.1 的验收证明的是「**事实成立后**切换能不能被播出」，**不是**「事实会不会成立」。
初版在真实课堂上实测：**一次都不会切**（四种场景 `applied=[]`，整节课决策点只被调用 1 次）。三处断链已修：

| # | 断在哪 | 后果 | 修法 |
|---|---|---|---|
| ① | `attach_variants` 在生产代码里从未被调用 | 真实课件 `plan.json` 里 `variants` 出现 0 次，候选池永远空 | `course.py` 加载时内存补挂（plan.json 不改）；`run.py plan` 落盘前写入；新增 `run.py variants` 就地补齐 |
| ② | 单元边界先走「学生提问优先」，director 块被跳过 | 学生一说没懂就产生待答问题 → 决策点被饿死 | 决策点保留在单元末尾，但**决策对象改成下一单元**，并补上「迟到的一次边界」（`_unit_exhausted`）与归位后的预取重发。**注意：本条最初曾用「在 rephrase 结束再加一个决策点」修，那个做法是错的，已被 C.6 取代。** |
| ③ | `Comprehension.CONFUSED` 声明了但从未被赋值 | v1「换说法」的条件在真实课堂永不命中 | 学生说没懂触发重讲时写 `confused`；并加 `_note_comprehension()` 闸：理解信号**只许升级不许降级**（否则页尾探针超时会把 confused 抹成 vague，直接毁掉 §12 ④ 的前后对比数据） |

**只有把注入点放到真实规模才会暴露的两个 bug**（6 单元夹具测不出来）：

1. 学生在**页尾探针窗口**里说没懂时，链路不经过 `_yield_now`（不设 `resume_point`），归位走兜底出口 —— 选了变体却没装上，表现为 `stats.applied=6` 而 `variant_applied` 事件只有 5 条，**静默丢一半**。修法：把「装变体」收口到 `_back_to_lecturing`（回到 LECTURING 的唯一入口），一处覆盖全部归位出口。
2. 页尾探针超时把该单元的 `confused` 覆盖成 `vague`，强信号被弱信号抹掉。修法见上表 ③。

**真实规模验收**（`tests/test_real_deck_scale.py`，42 页 / 177 单元整节课）：注入 6 次没懂 → **切换 6 次**，落在第 1/8/15/22/29/36 页页尾单元（跨 6 页 / 41 次翻页），`stats.timeout=0`、`error=0`、`applied==事件数`，耗时 3.03s（其中 2.1s 是探针窗口），`plan.json` sha1 未变。

测试总数 **219 passed**。**启用方式：必须显式 `CLASSROOM_DIRECTOR=1`**（默认关，见 §11 最后一行）。

### C.5 手动复现（在浏览器里看见切换）

### C.6 J 的定位纠正：它是「选路者」，不是「补救者」

C.4 修完之后，真实课堂确实会切了，但**切错了地方**。实测（学生只说一次「没懂」，S02-U01）：

```
[unit    ] 原讲 4 句
[rephrase] 换个说法（第1轮）…     ← 既有机制当场重讲
[resume  ] 好，我们回到刚才那里…
[unit    ] 变体 4 句               ← J 又让整段重播了一遍
```

**同一段被讲了三遍**，第三遍还只是加了「说白了，」前缀的同一段话。根因是两个机制在抢同一件事：既有的 `_gen_rephrase` 负责「学生没懂 → 当场换讲法」，而当时的 J 也在「换讲法重讲当前单元」。

**正确形态**（已按此实现）：

```
单元 N 讲完（单元末尾 = 唯一的分支节点）
   ↓ J 读事实：这格学生卡了吗 / 探针结果 / 理解信号
   ↓ 决定：下一单元 N+1 用 v0，还是用池里某条 targeting N+1 的变体
   ↓ N+1 开播时就用它，从第 1 句讲
```

这个定位与设计里其他几处是自洽的：§4.4 的 `target_unit` 指向具体单元、`expires_at_seq` 按单元序号作废、§7.4 的生产窗口是 `[+5, +15]` —— 候选本来就是给**未来那几格**备的货，J 的职责是决定走不走那条已备好的分支。

**硬约束：已经讲过的单元绝不重播。** 学生没懂时的当场重讲仍完全由既有 `_gen_rephrase` 负责，两者职责不重叠。

连带修正（两处，都是这次纠正逼出来的）：

1. **`Director` 的「事实来源」与「候选目标」必须显式分开。** 原先 `prefetch(unit)` 里 `facts.unit_id` 同时当了事实来源和候选筛选键，于是「事实来自 N、目标为 N+1」只能靠把预置候选的 `target_unit` 留空来绕过。**而空 `target_unit` 在 §4.4 里是「匹配任意单元」** —— 现在不出事只因池里永远只有一格的货；C 一旦启用，池里会同时有给 N+1 的空 target 预置货和给 N+5 的具体 target 货，J 就可能把**给 N+5 的变体装到 N+1 上**，学生听到另一格的内容，而且不报错。已改为 `prefetch/apply_at_boundary(unit, *, target_unit=...)` 双参数，目标单元也纳入作废条件。
2. **`apply_at_boundary` 的返回字典无条件带 `target_unit`。** 形状随参数变化的返回值会让所有读者（事件、日志、复盘脚本）都得写 `.get()` 兜底，而这种分支没有测试守着。

**验收**（`tests/test_variant_e2e.py` 与 `tests/test_real_deck_scale.py` 已按新语义改写）：说没懂的那一格只播一遍原讲（`applied==0`，逐句不重复）；下一格首句带引导语且 progress 从 1 起；真实课件整节课 6 次注入 → 6 次切换，落点是各自的后继单元（第 2/9/16/23/30/37 页）、跨 6 页、`timeout=0`、`applied==事件数`。

> **给后来者**：如果你发现自己在"让学生没懂时切变体"，先读 C.6。J 不补救，只选路。

### C.7 C 的真实接入（三体的第三体已闭环）

C 的 §7.2 流水线此前是完整的，只缺真实模型与生产接线。现已补齐：

| 件 | 位置 | 要点 |
|---|---|---|
| 真实 proposer | `agent/proposer.py`（`LlmProposer` / `build_proposer` / `parse_proposals`） | **独立 `LLM` 实例**（独立 httpx 连接池，§3.2 D2：不与课堂长流式生成抢连接）；`json_mode=True`、`think=False`；provider/model 可覆盖 —— `chat` 没有 model 参数，模型来自 profile，所以只能 `dataclasses.replace` 一份 Settings（课堂那份一个字节都不动） |
| 配置 | `config.py` | `CLASSROOM_AGENT_C` / `_PROVIDER` / `_MODEL` / `_TIMEOUT` / `_MAX_TOKENS`，全部带默认值；provider/model 留空 = 复用课堂那一份 |
| 生产接线 | `web.py` | 开关打开才构造 proposer、才 `create_task(serve_agent_c(...))`；`close()` 取消并 await。**默认路径零 import、零实例、零 task** |

#### 这一轮抓到的静默 bug：两套时钟混用

`pool.expire_stale(current_seq)` 的语义按 §4.4 是「**单元序号**超过 `expires_at_seq` 即作废」，C 也按单元序号记账（`ordinals[target]` + 余量）。但 `machine._prefetch_decision` 装载时传的是 `state.seq` —— 那是**句子计数器**（每吐一句 +1，一次「没懂」的重讲链就能涨 6）。

后果：**每一条 C 的候选都在到货前被判过期**。课堂上只表现为「后面再没换过讲法」；账面上那条候选确实写进了池子、`expired` 也如实记着，**没有任何报错**。

为什么此前测试没抓到：**预置变体用的是同一把尺子**（`presets.py` 把 `expires_at_seq` 也设成传进来的 `st.seq`），自己和自己比当然一致。只有 C 这个按文档语义记账的外来户才把差异暴露出来。修法：装载点的 `seq` 换成 `script.order_index(target.unit_id)`（`machine.py:864`）。

> 教训：两个名字近似的计数器（句子计数器 / 单元序号）混用，**不会报错，只会让功能静默失效**。凡是要跨模块比较「序号」的地方，先在注释里写清它是哪种时钟。

#### 启用与成本

```powershell
# TeachingFlow/classroom/.env
CLASSROOM_DIRECTOR=1      # 第一道闸：J + 预置变体
CLASSROOM_AGENT_C=1       # 第二道闸：C 的后台造货（独立开关）
# 可选：让 C 用别的模型，留空 = 复用课堂那一份
CLASSROOM_AGENT_C_PROVIDER=
CLASSROOM_AGENT_C_MODEL=
```

两道闸分开，因为爆炸半径不同：J 挂 = 课堂起不来；C 挂 = 少几条候选（§11）。只开第一道就是只有 J。

> **历史说明**：原原型仓库的 `start.cmd` / `start.ps1` 会在启动进程里**注入** `CLASSROOM_DIRECTOR=1` 与 `CLASSROOM_AGENT_C=1`
> （`config.py` 的 `load_dotenv()` 不覆盖已存在的进程变量，所以注入优先、`.env` 保持干净、开关是"每次启动"粒度）。
> 这两个启动器**没有随迁移带入 MAT**：MAT 的 `start-classroom.ps1` 只做"切目录 + 透传参数"，不注入任何东西。
> 所以现在只有两条路：写进 `.env`（持久），或启动前临时设进程变量（单次）：
>
> ```powershell
> $env:CLASSROOM_DIRECTOR='1'; $env:CLASSROOM_AGENT_C='1'
> powershell -ExecutionPolicy Bypass -File .\start-classroom.ps1
> ```
>
> 只开第一道就只设 `CLASSROOM_DIRECTOR`；关掉就什么都不设（默认关）。

成本口径：门卫把 40 次唤醒压到**实际调模型 8~15 次**（§7.3 / §12 阶段 3 验收①），每次约 3000 token 输入。默认关着等于零成本。

### C.8 分支树查看页（`/script`）

一套机制如果没人看得见它怎么走，就没人能判断它走得对不对。所以加了一个只读观测页：

| 端点 / 页面 | 用途 |
|---|---|
| `GET /script` → `web/script.html` | 页 → 单元 → 分支三层树，原生 JS，无构建 |
| `GET /api/script/tree` | 静态结构（一次拉取）：42 页 / 177 单元 / 每个单元的全部变体 |
| `GET /api/script/live` | 运行期叠加：当前单元、已切换的格及其分支、候选池三态、J 的六项计数 |

三条设计约束（都是踩过的坑）：

1. **绝不复用课堂页的 WebSocket。** `/ws` 是每连接建一个 Runner 的 —— 查看页再开一条 WS 就等于开了第二台状态机，两边互相覆盖。所以只读轮询，能和安全地和课堂同时开着。
2. **`variant_applied` 事件是权威来源，不读私有字段。** "哪些格被换了讲法、换成了哪一支"取自 metrics 事件（含 `probe_before` / `probe_after`）—— 那是为课后复盘设计的稳定接口，不是实现细节。
3. **首次加载一律全折叠。** 曾经按"含分支的页展开"来默认，但这份真实课件 177/177 个单元都有变体，条件恒真 → 打开就是 177 个单元摊开，正好违背了这页存在的意义。折叠态看结构（42 行读完流程 + 每页几个单元几支分支），展开态看细节。

**跟随当前**（默认开）：课堂在跑时自动展开当前页、滚动到当前单元；关掉后当前单元**仍然高亮**，只是不再替你展开和滚动 —— 关掉它的意思是"别替我做决定"，不是"别看当前在哪"。页面不可见时轮询自动暂停（`document.hidden`）。

`CandidatePool.items()` 是这一轮唯一新增的冻结接口，只给观测面用 —— 让查看页去摸 `_items` 私有字典，它会随池内结构的任何改动碎掉，而且一个查看页不该有改动课堂单一真相的能力。

### C.9 横向提交图（`/graph`）

同一份数据的第二种投影。C.8 那页竖着排（页 → 单元 → 变体），回答"这门课有几支、现在走到哪一支"；这一页把课堂脚本画成一张**走向图**：主体是一条从左到右的直线，线上的每个节点是一张**卡片**（`第 N 页 · 单元 k` + 正文摘要），卡片右缘一个**分支入口点**，支线从入口点以 45° 折进自己的泳道、走一张支线小卡片、再折回**下一张卡片**的左缘（走到课尾的那几条标「退出课堂」）。回答"这一格能换成哪几种说法、换掉之后落在哪、这门课有几条分支"。可拖拽平移、滚轮缩放（0.02×~2×）。两页各自成型、不共用一份 JSON：共用就意味着任何一边改字段都要先吵一次，而这两个问题本来就不是一个。

| 端点 / 页面 | 用途 |
|---|---|
| `GET /graph` → `web/graph.html` | 主线一条横线 + 支线泳道 + 页标尺 + 实时指针 + 缩略条，原生 JS，无构建 |
| `GET /api/script/graph` | 静态图（一次拉取）：主线节点序列、每条支线的插入点与泳道、分支计数 |
| `GET /api/script/live` | 与 C.8 同一条端点：指针位置、被换成哪一支、池三态 |

契约里四件不能改的事：

1. **`nodes[].n` 就是 `script.order_index(unit_id)`。** 它不是"排出来的"，和状态机装载候选时用的那把尺子同源。图上另起一套编号，前端点第 K 格、后端哼第 K 格会**静默**错开 —— 不崩不报错，只是换错了地方（与 C.7 那节"两套时钟混用"是同一类错）。
2. **`lanes.width = 1 + 单节点最大预置支线数`（上限 `_GRAPH_LANE_CAP = 12`）。** 宽度由整门课最大的那一格决定，边算边定会让同一张图里出现两套宽度；被截断时 `meta.truncated` 必须为真，否则前端只能悄悄少画几支。
3. **没有视图时 200 + `ok:false` + 中文 `hint`，绝不 500。** `course.mode != "deck"`（手写演示课件）与"课件在但没 plan.json"是两种不同的缺料，hint 分开说；降级载荷的 meta 键集合与成功时一致，前端不必为两种情况各写一套判空。
4. **每条支线显式带 `fork_node` / `merge_node` / `nodes[]`。** 跨度的两个端点写成字段，而不是让前端用哨兵值或"默认相邻"去猜：今天每条支线只有 1 个支线节点（岔出后绕一步就回主线，`merge == fork + 1`），但形状按任意跨度留好 —— 将来 Agent-C 产出多单元支线时，前端与渲染一行都不用改。`merge_node == len(nodes)` 表示走到课尾（"退出课堂"），`meta.terminal_branches` 按这个定义计数，**不按节点下标反推**（反推那版在跨度规则放宽时会静默少数）。

前端几何（`web/graph.html`）：主线卡片 `CW=120 × CH=52`、支线卡片 `BCW=84 × BCH=34`、卡片间隙 `GAP=140`（放得下两段 45° 折线 + 一张支线卡片）、泳道行高 `ROW_H=46`（必须 > (CH+BCH)/2 = 43，否则下泳道的支线卡片会压住主卡片）、折线横向偏移 `KNEE=46`（lane 1/2 的 |dy| 恰为 46 ⇒ 精确 45°）。真实课件 177 张卡片 = 46086px 宽画布（含课尾预留）。

卡片间距 `GAP` 给**每个**节点预留，不按"这个节点当前有没有支线"分配：C 的候选会在运行期落到任意节点上，按静态支线数算间距就得在候选出现时重排整条 x 轴（前缀和），实时指针会跟着跳。泳道 lane 1 上、2 下、3 上二层交替叠；C 现造候选接在 `lanes.width + i`，两类支线永不共泳道 —— 代价是**45° 只在预置泳道精确成立**，候选落在 lane 3–5 时（|dy| = 92/138）在 140px 间隙里只能是更陡的直线折段；要让它们也 45° 得把画布翻倍（84k px），不值得；真要改只动 `KNEE` 一处。

**交互**：`#gviewport`（`overflow:hidden`）包 `#gcanvas`，只改 `transform: translate3d(...) scale(k)`，不重排任何元素。滚轮以鼠标位置为锚点指数缩放（锚点数学 `cx=(px-tx)/k0 → tx=px-cx*k1`，缩放前后鼠标下的画布坐标不变）；按下拖动平移，**位移 > 4px 才算拖动**，否则仍算点击、照常打开详情，真拖过的那次 click 被吞掉；三个按钮「适应全课 / 100% / 回到当前」。**跟随当前**只在 `unit_id` 变化时居中。

**两级退化**：`k < 0.6` 卡片退化成光点、`k < 0.5` 再折叠支线（保留「显示支线」强制展开）。真实课件 354 条支线全展开会糊成一片，而 177 张卡片在远景也必然不可读 —— 这是"看形状"与"看内容"两个视角分开，不是省事。

`MIN_K = 0.02` 存在的**唯一目的**是让「适应全课」名副其实：177 张卡片 ⇒ 画布 46086px，1200px 视窗要一屏装下需 `k = 1200/46086 = 0.026`，取 0.02 留两成余量（900px 宽的窗口也能一屏看完全课）。这个数随几何变化必须重算 —— 一个写着"适应全课"却只装得下四分之一的按钮就是在撒谎。

**两个只在低缩放下才暴露的坑**（都出在"元素被 `scale(k)` 又乘了一遍"上）：

- **指针竖线与气泡要反向补 `1/k`。** 竖线宽度、气泡字号都跟着画布缩放走，`k=0.06` 时分别只剩 0.06px 与 0.66px —— 表现就是"指针不见了"。竖线按 `width = 1/k`、气泡按 `transform: scale(1/var(--gk))` 反补，屏幕尺寸恒定；缩放后必须重算指针几何（`placePointer()` 由 `applyTransform` 调），否则平移到新位置后指针是陈旧的。
- **缩略条视窗带要夹取。** `vw/(W*k) > 1`（k 很小时可见区已超出整条画布）时，不夹取会算出 `left + width > 100%` 甚至有负宽度。夹到 `left∈[0,99.6]%`、`width∈[0.4,100-left]%`。
- **退化必须只切 class，位置靠 margin 居中。** 卡片变光点时如果去改 `left/top`（哪怕只是缩小盒子），x 坐标就会变，指针和缩略条会跟着跳 —— 而缩放是每秒可能发生多次的动作。所以光点态用 `margin` 把内容居中，`left/top` 一个像素都不动（`#gcanvas.dots` 一个 class 决定全部）。

**两个不属于几何、但同样会静默出错的坑**：

- **新页面的 CSS 必须进 `_with_asset_versions()` 的 tuple。** 这一轮收尾时发现的缺口：`graph.css` 起初没进去，浏览器会拿着旧样式配新 HTML —— 正是那个函数 docstring 里写着要防的"我这儿没有那个按钮"。
- **`/api/script/graph` 零副作用是硬约束。** 它和 C.8 的 `/api/script/live` 一样会和正在上课的窗口同时被调用：一旦顺手建 Runner、推进状态机、或取一次 MCP 事件队列，课堂那边就安静地少一次决策，而这一页看起来完全正常。

**学生答疑不是一个分支。** 答疑只是指针**暂时离开**主线，所以图上不新增任何节点或支线：`phase` 属于 `{ANSWERING, RESUMING, REDIRECTING}` 时气泡写「答疑中 · 暂离主线」，图例里也写明这一条。把答疑画成分支，会让"这门课有几条分支"这个数字变成一句随时间变化的谎话。

**入口是功能的一部分。** 这一页最初交付时没有任何页面链接到它，结果被当成了不存在 —— 现在上课页、`/script`、`/review` 三处都有「课堂走向图」入口，`/review` 的降级分支与真实课件分支**都要有**（只补一条的话，手写演示课件模式下仍然找不到这一页）。

**边界**：这一页只把"支线"画出来，**不改状态机** —— 今天课堂拿到变体仍是"这一格换个说法后继续"，并没有真的走进一条多单元支线。真要让导演把课带进支线讲几格再回来，是 machine / decider / producer 一起动的另一件事。

测试：`tests/test_script_graph.py` 27 条（与 `test_script_tree.py` 的 10 条合跑全绿；其中一条专钉"四页都能找到这一页"）。它们钉住 `n` 与 `order_index` 全等、`0 ≤ fork < merge ≤ len(nodes)`、非末节点 `merge == fork+1`、末节点 `merge == len(nodes)` 且 `meta.terminal_branches` 与全量计数一致、支线节点文本逐字取自变体（不伪造内容）、泳道从 1 连续、两种降级都 200 且 meta 键集合一致、零副作用（`web.Runner` 换成"一建就 raise"后连调三次载荷全等）、`/graph` 页 HTML 含 `id="graph"` 且 `graph.css` 带 `?v=`。页面的锚点数学、4px 拖动阈值、课尾不越界、低缩放折叠、三按钮 tx/ty/k 由一次性 DOM 桩 smoke 验过（仓库不留桩文件）。

### C.10 一键启动与启动台（`/hub`）

> **历史说明**：原原型是双击 `start.cmd` → `start.ps1`，启动器负责：找到 `run.py`、缺 `.venv` 就建、依赖缺失就装、`.env` 缺失就按 `.env.example` 复制并停下来提醒、provider 是 ollama 时确保本地模型服务在跑、端口被占就认为课堂已在运行并直接开浏览器、打印横幅、**等服务真的接受连接之后再开浏览器**、默认注入 `CLASSROOM_DIRECTOR=1` 与 `CLASSROOM_AGENT_C=1`（`-NoDirector` / `-NoAgentC` 关掉），并按 `-Warmup` / `-Check` / `-NoBrowser` 分开关。**这一整套启动器未随迁移带入 MAT**：现在由仓库根 `start-classroom.ps1`（只切目录 + 透传参数）加 `setup.ps1`（装依赖、生成 `.env`）分担；启动台 `/hub` 本身没变。

**双击之后落到 `/hub`，不是一个标签页开五个地址。** 人类页面已经有五个（上课页 / 课堂走向图 / 分支树 / 脚本审核 / 课件预览），一次全弹出来主次不分 —— 审核页与预览页多数时候并不需要看；只开上课页则等于把其余四个藏起来（`/graph` 就吃过这个亏：页面早就跑得起来，却没有入口，于是被当成"没做"）。所以启动台是**入口页**，不是新功能：一屏列全，带每页用途说明，上课页与走向图排在第一组。

三条约束：

1. **启动台只读、且只在加载时读一次 `/api/script/graph` 与 `/api/script/live`**（用来显示"课堂在跑没有 / 哪份课件 / 几页几单元几支线"）。它**不轮询** —— 每秒轮询的活儿已经由 `/graph` 与 `/script` 各自在做，入口页再开一条只是白烧 CPU。`tests/test_hub.py` 里有一条用例专门断言页内不出现 `setInterval`。
2. **样式写在页内，不单开 `hub.css`。** `_with_asset_versions()` 的 tuple 每加一个文件就多一处"忘了加"的机会（`graph.css` 就差点漏掉，表现是"新页面配旧样式"）。一页只被启动时看一次的静态页不值得再引入一个资源；页内 <style> 随 HTML 走 no-store，天然不会缓存出错。
3. **链接就是功能清单，测试按清单钉。** `tests/test_hub.py` 把 `ENTRIES = ("/", "/graph", "/script", "/review", "/preview", "/mcp")` 作为唯一清单：少一条就失败，路由没注册也失败，页里引用了不存在的 `/static/xxx` 同样失败。加一页就加一条 —— 这是这个文件存在的全部意义。

`-LandingHome` 可以在需要时改成落回上课页（`/`），其余行为一致。
