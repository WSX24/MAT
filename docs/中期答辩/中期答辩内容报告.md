**3.3 双脑三体内核**

- **P 备课 / J 选择器 / C 造分支**（`双脑三体方案设计.md:119`）：P 在课前一次性产变体，J 在单元边界从候选池里挑，C 以常驻形态持续造分支。
- **J 不是 agent，这是有意的。** `双脑三体方案设计.md:127` 给的理由是「agent = 循环 + 工具 + 历史，J 三样都不需要」，做成 agent 等于给它装上必须甩掉的三样负担、「直接摧毁延迟上界」。代码如实落地：`RuleDecider`（`director/decider.py:33`）纯规则、`decide`（`:40`）零模型调用，`LlmDecider` 只留一个 Protocol 缝。所以 J 的延迟是可断言的，不是可期望的。
- **CandidatePool 是单一真相**（`pool.py:169`，`CAP = 5` 在 `:173`）：上限不是省内存，是给 J 的输入长度封顶——`:160-168` 写明「5 条 × 30 字是一条整体纪律」，并明确拒绝"某种载荷值得多写几个字"的特例，否则边界上的等待会跟着候选的种类走。驱逐判据同样可证明：只用单调比较（`:205`，牺牲品期距不许超过 `EVICT_HORIZON_UNITS = 17`，`:43`），不引入新时钟，于是"越靠近当期越优先"是可论证的。

**3.4 前端与出片引擎**

- **SlideView 是 DOM 重绘，不是整页截图。** `SlideView.tsx:3` 声明固定 1280×720 逻辑画布、整块 `transform: scale()` 自适应（`:56`），再按元素类型分派 `picture`（`:94`）、`table`（`:101`，真 `<table>` 渲染在 `:228-246`）、`svg`（`:280-319`）。直接后果是课堂上的文字可选中、缩放不糊——这是选 DOM 而不选位图的唯一理由，也是"看起来像 PPT"与"真的是文档"的区别。
- **前后端靠契约解耦。** `protocol.ts` 只有 48 行，`KINDS`（`:40`）列出 9 种服务端帧，`parseServerFrame`（`:42`）遇未知 `kind` 直接 `return null`（`:46`）：后端加新帧不会让旧前端崩。离线演示在 `mock.ts`（645 行）的 5 个场景 `default/empty/error/slow/unprepared`（`:11`），可用 URL 参数切换（`:18`）——预录屏用的就是它。
- **出片分工：pipeline 不写 pptx。** `s5_render.py:79` 起 `PPT-Agent/pipeline.py` 子进程管分页与 SVG，真正的 pptx 转换在 `svg_to_pptx.py`（`requirements.txt:4` `python-pptx>=0.6.21`）。`s5_render.py:173-174` 有一条硬防御：产物若解析到 `ppt-master` 目录内就抛 `RuntimeError` 拒绝交付，因为那是"别人的旧产物"——说明我们预见过"看起来成功但产错文件"这种失败模式。
- **provider 覆盖。** PPT-Agent 声明 7 家（`agent.py:164/170/183/189/195/201/207`）+ 自定义网关分支（`:253`/`:289`）共 8 条路；课堂侧 ollama / opencode / opencode_go（`config.py:410`），deepseek 按需出现（`:454`）。两套配置不互相污染，出片换模型不影响上课。

## 5 风险与自辩

**Q1 你们的多 agent 协作体现在哪？** 三处，都能指到代码：产物契约（`s5_render.py:247` 连页数都要重数）、确定性门控（`gates.py:39` vs `:43`）、共享状态与并行（`pool.py:173` 的 `CAP=5`；`machine.py:1659` vs `:1674`）。我们不宣称有 agent 间对话协商——`critic|vote|arbitrat|debate|consensus` 全仓只有 1 处误命中。

**Q2 出片跑通过吗？** 在本工作区没有。8 次运行全 MOCK、0 个 manifest 有 `s5_render`、Key 值为空。代码路径完整，缺一次带 Key 的真实执行。这是路线图 ②，也是当前最大缺口。

**Q3 为什么不用 LangGraph 或 AutoGen？** 瓶颈不在编排抽象，在每一步产物的可判定性。`CHAIN.md:175` 里每步的失败语义是逐条写死的领域规则（S1 不能降级、S3 缺模块只警告、S4 兜底），通用图调度表达不了；引入框架等于把 3,202 行有明确约定的流水线换成需要重新验证的运行时，风险与收益不匹配。

**Q4 480 条测试覆盖的是什么？** 大头在课堂侧：`test_api_contract.py` 1,209 行（HTTP 契约）、`test_machine.py` 843 行 19 条（状态机与 I1–I6）、内核相关约 135 条（P/J/C）。**不覆盖的是流水线主干**：`core/`+`steps/` 3,202 行零 pytest，只有 16 条 smoke 与 promptlint。这条我们主动说，不等评委自己发现。

**Q5 没有 Key 怎么证明能出片？** 静态层有三段：调用点 `flow.py:216`、子进程 `s5_render.py:79`、转换器 `svg_to_pptx.py`；而且 `s5_render.py:173-174` 会拒绝交付旧产物，说明这条路径被认真对待过。但静态证据只能证明"写了"，不能证明"跑得出"。所以 ② 项给的是可验证判据（manifest 含 `s5_render`、`05_ppt_<uid>/` 存在、页数等于 S4a 决策值），不是口头承诺。

**Q6 双脑三体写完了为什么不算完成？** 因为没接线。`grep -rn director app studio` 命中 0，`runner.py:229` 的 `Machine(...)` 没有 director 形参。一个只在测试里被调用的内核，对课堂的影响是零。我们把它记成「已实现 / 未装配」，不记「已完成」。

**Q7 中期到结项还剩什么？** 九项，见第 4 节。①②③ 是必须打通的端到端与保险，④⑤⑥⑦⑧⑨ 可以结项后推进。判断标准很硬：② 没有 manifest 存证、① 没有 `events` 记录，都算没做。

**Q8 课堂侧的"多智能体"是不是名不副实？** 上课期只有 4 个 prompt 角色（`classify` `llm.py:836`、`answer_stream` `:867`、`rephrase_stream` `:891`、`yield_phrase` `:909`），共用同一个 `TEACHER_PERSONA`（`:375`，用于 `:405/457/496/941`），靠 system 段切换：这**是**会话内角色切换，不是多 agent 进程，我们不计入多智能体；讲解正文也不问模型，直接来自 `plan.json`。多智能体的位置在备课时段（P）与单元边界（J/C），不在讲课过程中——这个边界我们讲清楚，不含糊。
